## 2. 守りの決まり

- 運営の API は、運営の人で、その「できること」を持つ人だけ（`ops:distribute`・`ops:plan_propose`・`ops:plan_decide`・D-128.70）。顧客の画面の API とは混ぜない（ZT9）
- 全部のワークスペースに効く操作（業務の型の版を出す・戻す・ひな形の版を出す・値段を決める）は本人確認を取り直す（ZT5）
- 値段は作る人と決める人を分ける。自分の案は決められない（決められる人が 1 人のときだけ例外・D-128.72）
- どのワークスペースがどの版を使っているかは数だけ見る。中身は見ない

## 3. 途中で見つけて直したこと

- **運営が配る「ひな形」の画面がキャンバスに無かった。** 決定（D-125.72：会社はひな形を取り込んだら独立して使い、新しい版が出ると知らせが届いて差分を見て取り込むか選ぶ）と行為（A128）はあったのに、配るものの画面は業務の型・操作・プランだけだった。配るもの › ひな形（種別とチケットの形・作業の段・分類の軸・層の形）を足した

## 4. 決めたこと

この回で新しく決めてもらうことは無かった（D-125.72・D-126.3・D-126.5・D-126.19・D-126.23・D-128.70・D-128.72 のとおり）。
