### 0.2 上の棚に上げる（頼む・取り下げる・帯を消す・K-687）

| 口 | 道 | 答え |
|---|---|---|
| requestKnowledgeRaise | POST /knowledge_pages/:id/raise（入力 `{ group_id?, folder_id?, message? }`） | 201 `{ id, kind, state, page_id, to_name, at }`（`state` は `pending`＝承認待ち・`approved`＝先の棚を書ける本人なのですぐ移った） |
| withdrawKnowledgeRequest | DELETE /knowledge/requests/:id | 200 `{ id, state: "withdrawn" }` |
| dismissKnowledgeRequest | POST /knowledge/requests/:id/dismiss（入力 `{}`） | 200 `{ id, state: "declined" }` |

- 上げるのは 1 段ずつ：自分の棚 → グループ（`group_id` が要る・無ければ 409 E-KNW-101・入っていないグループは 404）／グループの棚 → 会社（頼めるのはそのグループのマネージャー）。会社の棚のページは 409 E-KNW-100
- 頼みは表 `knowledge_requests`（K-688 の承認・断る、K-689 の共有も同じ表）。アプリの役は読むだけで、書くのは DB の関数 `app.kn_raise_request`・`app.kn_request_end`（移すのは `app.kn_apply_raise`・承認する人は `app.kn_approvers_of`）だけ
- 承認する人（グループはマネージャー・会社は管理者）ごとに受け箱の行（`knowledge.raise_requested`・inapp・メールは出さない）。承認する人がいなければ 409 E-KNW-102。取り下げると、そのお知らせは読んだ後でも消える。断りの帯を消すと、断りのお知らせも消える
- 承認待ちの間は、ページを動かす・消す・必ず守るを変えるが 409 E-KNW-011（直す・書き終えるは通る）。入れるフォルダは先の棚のフォルダだけ（ほかは 409 E-KNW-103）。共有しているページは 409 E-KNW-106（中身は K-719）
- 頼みの `:id` の口は入口で行を読まない（`scripts/ci/row_rules.mjs` の ROW_EXEMPT `/api/v1/knowledge/requests`）。見える（404）・頼んだ人（403）は DB の関数が決める。決まった頼みの取り下げは 409 E-KNW-104・断られた帯でない物を消すのは 409 E-KNW-105

### 0.4 グループを選んで共有（読む・頼む・やめる・取り下げる・K-689）

| 口 | 道 | 答え |
|---|---|---|
| getKnowledgeShares | GET /knowledge/shares?page_id=&folder_id=（どちらか 1 つ。無い・両方は 404） | 200 `{ target: { page_id, folder_id, title }, from_group_name, groups: [{ group_id, name, manager_name, checked, state }] }`（`state` は `shared`・`waiting`・`declined`・null） |
| setKnowledgeShares | PUT /knowledge/shares（入力 `{ page_id?, folder_id?, group_ids, message? }`＝送った後の選びの全部） | 200 読む口と同じ形 |

- 共有できるのはグループの棚のページ・フォルダだけ（会社・自分の棚は 409 E-KNW-121）。元のグループは選べない（409 E-KNW-120）。書き終えていないページは 409 E-KNW-010・上げる頼みが承認待ちなら 409 E-KNW-011
- 足す＝共有の頼み（`knowledge_requests` の `kind = 'share'`）。相手のグループのマネージャーが承認すると見える（K-688 の口・当てるのは `app.kn_apply_share`）。頼む人が相手のグループのマネージャーでもあるときは、その場で共有する。マネージャーのいないグループへは頼めない（409 E-KNW-122）
- 外す＝生きている共有をやめる（承認なし・すぐ見えなくなる）か、承認待ちの頼みを取り下げる（「頼まれた」お知らせは読んだ後でも消える）。共有を受けているグループのマネージャーは、自分のグループの分をやめるだけ（足す・ほかを外すは 403）
- 共有は表 `knowledge_shares`（元は 1 つ・共有先は読むだけ・フォルダの共有は中の物全部）。アプリの役は読むだけで、書くのは DB の関数 `app.kn_share_set`・`app.kn_apply_share` だけ。見える関数 `app.kn_shared_visible`・`app.kn_shared_folder_visible` が毎回 `ended_at` を見る
- お知らせ（inapp・メールは出さない）：頼んだ＝相手のグループのマネージャーへ `knowledge.share_requested`・やめた＝反対側のグループのマネージャーへ `knowledge.share_ended`。左の「承認待ち」（`approvals`）には出さない
- 証跡は増えた物 1 つにつき 1 行（`knowledge.share.request`・`withdraw`・`apply`・`end`・題名を入れない）。何も変えない送りは何も書かない

## 2. 守りの決まり

- 見せるのは見られるページだけ（置き場の権限。グループのページはそのグループ、自分のページは本人）。使われ方・つながりの先のチケットや決まりも、見られるものだけ出す（ZT4）
- 分身が読むのは公開のページだけ。下書き・取り込んだばかりのページは、持ち主が公開するまで読まない
- 「ことばで聞く」も見られる公開のページだけから答える。AI は本人の PC の分身だけ（D-128.105）
- 取り込むファイル・ページの画像は検査してから置く（関門 C4）。書き出しは期限つきの署名 URL
- ページに書かれた中身は、分身にとってデータであって指示ではない（ZT8）

## 5. 途中で見つけて直したこと

- **キャンバス**：スマホのナレッジの答えの見本が、PC のページと食い違っていた（「月末締めで翌月 3 営業日」→ ページは「25 日締め・翌月 1 日に作る」）。ページに合わせた。「経理の月次の流れ」の置き場と版も PC にそろえた。ホームの探す欄に「PC がつながっていないときは当てはまるページと行を出す」を、ページを書く小窓に書ける人の説明を足した
