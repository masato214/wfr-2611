## 2. 守りの決まり（ゼロトラストの決まりから）

- ログイン前の API（public）は、有る無しを漏らさない（「そのメールは登録されていません」と言わない）・IP ごとの上限を厳しく・失敗が続くと鍵をかける
- パスワードを変えた・再設定した・端末を外した ときは、画面も PC（Bridge）も全部切る（D-125.140）
- 大事な操作（2 段階を付ける／外す・バックアップコード・パスワード・パスキーを外す・管理者が 2 段階を戻す）は、直前の本人確認が無いと 403（ZT5）
- セッションの期限（操作が無いと 12 時間・最長 7 日）と、IP・国・端末の急な変化で入り直させるのはサーバーの仕組みで行う（ZT6・作る段で）

## 3. 途中で見つけて直したこと

1. **自分の安全の設定の API が「ログイン不要」で作られていた。** 画面が登録の流れの画面として扱われていたため、作り方が画面単位で決めていた。API ごとの権限からログインの要否を決めるように直し、検査（ZT2）で「権限が public でないのにログイン不要」を赤にした
2. **契約の外に手で書いた道すじが 87 本ある**（`apps/api/src/auth/*.ts`：今の登録・ログイン・招待・PC（Bridge）とのやり取り・分身の会話の流れ・成果物・預けたログイン情報）。「誰が呼べるか」の検査の外にあるので、検査の「実装の残り」に数を出すようにした。PC と預けたログイン情報は次の「自分の設定」で契約に入れる
