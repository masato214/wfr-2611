# 第1フェーズの API ── チケット（案・2026-11-03）

キャンバスのチケットまわりの画面 1 枚ずつ「何を読み・何を押すか」から逆に出した（D-128.78）。前の作り方（行為 1 つ → 表 1 つ → API 1 本）では、詳細から開く小窓・本文の版・テスト仕様の案・やり取り などが出てこなかった。

- 道すじはすべて `/api/v1` の下。チケットは id でも番号（`EG-128`）でも引ける（Backlog の `issueIdOrKey` と同じ）
- 書く API は、認可 → ポリシー → 承認 → 副作用 → 記録 の順（今の決まりのまま）
- 外に出るもの（メール・成果物を送る）はこの API では起こさない。分身の実行（Bridge）と承認を通る

参考：GitHub はやり取りと変更の記録を 1 本の流れ（timeline）で返す（https://docs.github.com/en/enterprise-server@3.17/rest/issues/timeline）。Backlog は課題を番号でも引け、件数だけを返す API を持つ（https://developer.nulab.com/docs/backlog/api/2/count-comment）。
