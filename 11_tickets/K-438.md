## 目的

過去のチケットから新しいチケットを作る（複製・A129）口を作る。**複製は別の口ではなく、作る口 `createTicket`（POST /tickets・K-60 が作り、K-437 が新しい形に直した）の入力に 2 つを足した物**。今の契約は strict で、この 2 つを送ると 422（知らない項目）になる。

- `duplicate_of`（元のチケットの id・uuid）と `copy[]`（写す物の名前の並び）を受ける。写す物は **本文（body）・担当者と承認する人（assignee・承認する人は担当者と同じ人〔D-128.25〕で、写すのは担当者の 1 つだけ）・項目（fields）・確認項目（specs）・つながり（links）・子チケット（children）** の 6 つ（D-150.6）。添付は段 5 では作らない（D-150.9）ので、`attachments` を入れると 422。前の版の `references`（参照するもの）と `test_specs` の名前は無くなった（422）
- 写す物の中身（D-150.6）：
  - **本文**：元の本文（`ticket_sections` の鍵 `body` の `doc`）。**チェックの箱は全部外して写す**（`taskItem` の `attrs.checked` を false に）。見出し・段落・表・薄い字の説明（`attrs.ghost`）は元のまま。`text` は口が `docToText` で作り直す（DB に doc → text を書かない・K-561 の決め）
  - **項目**：優先度と理由・予定時間（`estimate_minutes`）・会社が足した項目の値。**期限と開始日は写さない**。期限は画面が元の日付を入れて見せ、人が直して送る（口は入力の `due_on` をそのまま使う・日付の読み替えは人が直す・D-150.6・K-446 の決めと同じ。元の期限が過ぎていて直さないなら今日より前なので 409・E-VAL-012）。**開始日は写さず、画面も送らない**（入力に `start_on` が無ければ空。小窓に開始日の欄が無いので、元の開始日を黙って送らない）。会社の項目は、新しい種別に出ない項目・値が今の決まり（型・選択肢）に合わなくなった項目は**黙って写さない**。元に値が無い項目は入力の `fields` を使う
  - **確認項目**：文・`check_kind`・出どころ（`source`・`source_ref_id`）は元のまま。**チェックは外す**（`checked_at`・`checked_by_member_id`・`checked_by_ai` を空に）・版 1・作った順・消した行は写さない
  - **つながり**：元の「関連」のうち、相手が消えていなくて呼んだ人に見える物だけ（向きは問わない）。元の派生元・元から派生した先の線は写さない
  - **子チケット**：元の直接の子（消していない・呼んだ人に見える・種別が消えていない）を、複製と同じグループに、親＝複製で作る（孫は写さない）
- 写さない物：決定ログ・申し送り・成果物・実行の記録・やり取り・業務の型・添付
- **元へのつながりは copy に関わらず残す**：`ticket_links` に from＝複製・to＝元・kind `derived_from` の 1 行（D-150.27。`tickets.derived_from_ticket_id` は使わない）
- **写すと選んだ物は元から取り、入力の同じ欄は（元に中身がある限り）使わない**。写さない物は K-437 の作り方のまま（入力のとおり）
- 元は**読めれば足りる**（書く権限は要らない・見える範囲は D-125.95・D-128.115）。元が無い・消えた・別の会社・他の人の取り込みの下書き・見えないグループは、どれも同じ 404（存在を漏らさない）

画面は持たない（複製の小窓と、作る面の「過去のチケットから複製」の元を選ぶ小窓は K-446）。

## 前提と制約

分類: CRUD, PERM

- **作る関数 `app.ticket_create`（K-437）は作り直さない**。複製は同じ取引の中で 3 つを順に呼ぶ：①`app.ticket_duplicate_read`（元を止めて読み材料を返す・断るなら何も書かない）→ ②口が材料から作る体で `app.ticket_create`（K-437・断りはその答えのまま）→ ③`app.ticket_duplicate_apply`（確認項目・つながり・子・派生元の線・お知らせ・証跡を書く）。3 つとも同じ `withTenant` の 1 取引。③の途中で落ちたら例外で取引ごと戻る（口は 503・E-PAGE-003・ログは場所と例外の種類だけ。K-437 の口が持つ「取引の例外を口の中で捕まえて 503・E-PAGE-003 を返す」をそのまま使う）。②が断った（ok:false）ときは何も書かれていないので①の `for share` が解けるだけ
- **本文の箱を外す・text を作るのは口（TypeScript）だけ**（`apps/api/src/features/F4/create-ticket/duplicate.ts` の `uncheckDoc(doc)`・`toTicketBody` は `@kaname/contracts`）。DB は text も箱の印も作らず、渡された `{doc, text}` を書くだけ（L-002：doc → text の実装を 2 つ持たない）。子の本文も同じ（①が子の doc を返し、口が箱を外して text を付け、③に渡す）
- **①`app.ticket_duplicate_read(p_src uuid, p_copy text[], p_kind uuid, p_parent uuid) returns jsonb`**：会社の人でなければ `{error:'not_member'}`・元が無い／消した／別の会社／`app.ticket_visible` でない（他の人の取り込み中の下書きを含む）なら `{error:'gone'}`。元の行と、copy に children があれば写す子の行を `for share` で止める（複製の途中で消されない）。copy に children があり、新しいチケットの段（親の鎖を数えて +1）に子 1 段を足すと 3 を超え写す子が 1 人以上いるなら `{error:'depth'}`。答え `{ok:true, src:{assignee_member_id, priority, priority_reason, estimate_minutes}, body:{doc}|null, fields:{<項目の id>:値}, children:[{id, body:{doc}|null}]}`。`body` は copy に body があり元に本文の行（鍵 body・消していない）があって text が空でないときだけ（無ければ null＝入力の本文を使う）。`fields` は copy に fields があるときだけ、元の値の行（消していない）のうち、項目が消えていない・`custom_field_kinds` に行が無いか `p_kind` が入っている・`app.custom_field_normalize`（K-564）が値を通す物だけ。前からの区画（本文の行が無いチケット）は読まない
- **②口が作る体**：入力に対し、copy の名前に応じて次を重ねる。`body`＝元の本文を箱を外して `{doc, text}`（元に無ければ入力のまま）／`assignee_member_id`＝元の担当者／`priority`・`priority_reason`・`estimate_minutes`＝元の物／`fields`＝元の値の上に、元に値の無い項目だけ入力の `fields` を足した物／`specs`＝copy に specs があれば入力の `specs` を捨てる（写しは③が書く）。copy に無い名前は K-437 の作り方（入力のとおり）
- **③`app.ticket_duplicate_apply(p_new uuid, p jsonb) returns jsonb`**（`p` は `{source, copy, children:[{id, body:{doc,text}|null}]}`）：copy に specs があれば元の確認項目（消していない）を作った順に `test_specs` へ（上の写し方・`created_by`＝呼んだ人）／links があれば元の関連（相手が消えていなくて `app.ticket_visible`）を `app.ticket_link_put(新しいチケット, 相手, 'related')` で／**必ず** `app.ticket_link_derive(新しいチケット, 元)`（K-441。答えに error があれば例外で戻す）／children があれば子ごとに、元の子の題名・種別・優先度と理由・予定時間・担当者を写して**新しい子の行を直に書く**（番号は `app.ticket_create` と同じ採番・段は未着手・親＝新しいチケット・グループは同じ・期限は元の子の期限と新しいチケットの期限の早い方・開始は元のまま〔期限より後なら空〕・担当者が選べなくなっていれば呼んだ人）。子の本文の行（鍵 body・位置 0・版 1・版の行 1）は口が渡した `{doc, text}`。子ごとに `app.ticket_link_derive(新しい子, 元の子)`。**子には確認項目・項目の値・つながり・孫・業務の型を付けない**。担当者が呼んだ人でない子ごとに受け箱 `ticket.assigned` を 1 つ（dedupe_key `ticket.assigned:<子の id>`・本文は題名と番号だけ・メールは出さない）／証跡 `audit_events`（action `ticket.duplicate`・target tickets・target_id＝新しいチケット・choke_point_id C2・payload `{source_ticket_id, copy（入力の順）, children（写した子の数）}` だけ）。複製の担当者への受け箱は K-437 の作る関数が書く。答え `{children: n}`
- **断る順と番号**（控え帳 2026-11-20 16:51・20:50・21 日 01:15：422＝契約に書ける形だけ／404＝無い・見えない／409＝今の状態ではできない。404・409 の体は `{error, code, message, action, undo, support_code}` だけで欄・details・detail を付けない）：元が見えない（①）＝404・E-DUP-001／子を写すと 3 段を超える（①）＝409・E-DUP-002／そのあとは K-437 の断りのまま（置き先に書けない 403・種別・担当者・親・知らせる人が選べない 404 E-PAGE-001・期限が今日より前 409 E-VAL-012・開始が期限より後 409 E-VAL-028・会社が必須にした項目が空 409 E-FLD-004 など）。形の誤りは 422（欄 `copy`・`duplicate_of`）。書き込みは③だけで、断りは全部③の前に出る
- `copy` の形：6 つの名前（body・assignee・fields・specs・links・children）の並びで重複なし（契約の `items.enum`・`uniqueItems`）。知らない名前・添付（attachments）・参照（references）・文字だけ・重複は 422（欄 copy）。元の無い copy（空の配列も）は形全体の決まりで 422。`duplicate_of` は無ければ無し・あれば uuid（**空文字・null・数・uuid でない文字・NUL を含む文字は契約の入口が先に 422**。ここで空を「無し」にしない）
- 担当者を写す・子の担当者のとき、**選べなくなった人**（抜けた・止められた）は：複製の担当者なら 404・E-PAGE-001（K-437 の関数の断りのまま・欄なし）、子の担当者なら作った人に直す
- 知らせは画面の中の受け箱だけ（メールは出さない・D-125.130）。元は変えない（行・本文・版・確認項目・項目の値・子・つながりを書き換えない・K438-API-003）
- 子の数の上限は置かない（D-150.28 に無い）。子を写す所は子ごとの繰り返しで、文は子の数に比例する。守りは入口の送る量 1MB（口が子の本文を作った後の DB への引き渡しの大きさは、元の子の本文の和なので 1 つの取引の長さで受ける）
- 前の形のチケット（本文の行が無く区画だけ・K-575 が移すまで）を元にした複製は、**本文を写さず入力の本文を使う**（区画は読まない・K438-API-005。K-575 の移しが入れば全部のチケットに本文の行がある）
- PC をつなぐ前でもできる（D-127.8）。外のサービス・メール・PC は呼ばない。試験の準備は本物の DB の行を直に入れる（元の確認項目・項目の値・つながり）
- 試験を書いた後は変えない（変える必要があれば切る段に戻す）
