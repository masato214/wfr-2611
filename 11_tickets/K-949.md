## 目的

顧客（R1〜R3）が「困ったとき・お知らせ › 問い合わせる」から運営に聞く口 `createInquiry`（POST /api/v1/inquiries）を作る（今は 501）。答えの形は K-948 の「画面が使う答えの形」（`MyInquiry` の 7 欄）。

- 何について（4 つ）・題・内容・検査の済んだ添付（K-950 が上げた物）・いま見ている画面の情報（D-128.71）で問い合わせを 1 件作り、最初の書き込みを会話に置く
- 作った問い合わせは運営の受信箱の「担当なし」の箱に入る（状態 open・担当なし。受信箱の口は K-973）。運営へのメール・鈴は出さない（D-125.130：知らせは画面の中だけ。運営は受信箱の数で知る）
- **見えるのは書いた本人だけ**（D-156.25）：今の行の守り（同じ会社の全員が読める・inquiries の edit を持つ人は他人の問い合わせも書ける）を、本人だけに作り直す
- 運営の社内メモの印 `messages.visibility`（`all`／`ops_only`）を足し、本人は自分の会話でも ops_only を読めない形にする（ER 図 508 行の決め。書くのは K-975）

読む口は K-951、返事を書く・済みにするは K-952、添付を上げるのは K-950、画面は K-953。

- **入力の形（契約＝422）**は K-948 の断片が持つ（topic 4 つ・title 1〜100・body 1〜4000・attachment_ids は uuid 5 つまで・context は object・余計な欄は受けない）。**題・内容の空白だけ**（全角の空白・タブ・改行を含む）も契約の形で 422 にする：K-948 の断片の VALUE_RANGES の createInquiry の title・body の `"pattern": "\\S"`（D-156.38・K-948 に足した・K948-DC-017）で断る（K949-API-003 が見る）。NUL は入口が 422（K-427）
- 題と内容は前後の空白（全角・タブ・改行）を落として残す（NFKC にしない）。字数の上限は契約のまま（D-130.1：守りは送る量 1MB）
- **画面の情報 `context`**（D-128.71）：鍵 `path`（文字・500 字まで）・`at`（文字・40 字まで）・`browser`（文字・200 字まで）・`pc`（真偽）だけを残し、知らない鍵・型の違う値・長すぎる値は落とす（422 にしない：画面の情報は付けるかを選べる付け足しで、欠けても問い合わせは届く。チケットの中身や会話を運営に渡さない）。無ければ `{}`
- **添付**（`attachment_ids`）：K-950 が作る `attachments` の行（`owner_type = 'inquiry'`・`uploaded_by` が本人・会社が本人の会社・消していない）だけを付けられる。無い・別の人・別の会社・消した → **404 E-PAGE-001**（欄・details・detail を付けない＝在るかを漏らさない）。検査が済んでいない（`scanned_at` か `storage_ref` が空）・もう付けた（`owner_id` がある）→ **409 E-INQ-001**（欄なし）。同じ id の重なりは 1 つにする。付けたら `attachments.owner_id` を最初の書き込みの id にし、書き込みの `attachments` に `[{ id, name, size }]` を並びのまま入れる。同時に同じ添付を付けたら片方だけ通る（行を `for update` で取る）
- **断る番号**（控え帳・D-156.12・D-156.17）：先方の権限の人（role client）は入口が 403（契約の auth member・op.ts）／ログインなし 401／上限 429（契約の 60/分/人）／DB の失敗 503 E-PAGE-003（何も残さない）
- **関門の宣言** choke_points は契約の口と同じ [C2, C4, C6]（KC4）。この口が通るのは C2 だけ：C4 の検査は K-950 が上げるときに済ませ、この口は済んだ印を見るだけ。C6 は呼ばない（D-125.130・運営は受信箱の数で知る）
- ログに題・内容・画面の情報・ファイルの名前を出さない（会社の id・口の名前・例外の種類だけ）
