## 目的

ナレッジの画面（K-682）の左の木を出すための口 `getKnowledgeTree`（GET /api/v1/knowledge/tree）を作る（契約は K-675 が宣言済み・今は 501）。物は「ナレッジのページ」1 つで、棚は **会社・グループ・自分** の 3 つ。答えは、今の人に**見える**フォルダとページを棚ごとの木にして返す（土台 3.1 の `KnowledgeTree`）。

- 見える物の決めは K-674 の DB の守りと関数（会社＝社内の全員／グループ＝そのグループの人／自分＝本人だけ。下書きのページは持ち主だけ）。口はその上で読み、口の文でも棚で絞る（守りの 2 重）
- ページの印（`mark`）：下書き（`draft`）・写し（`copy`）はこの葉が決める。**承認待ち（`waiting`）・断られた（`declined`）・承認待ちの数・見直すページの数・共有された物だけのグループは、後ろの葉（K-687・K-688・K-695・K-689）が作る表に頼る**ので、この葉は「無いときの形」（印なし・0・空）で返し、**4 つの小さい関数のファイル**を置く。後ろの葉は自分のファイルの中身だけを差し替える（`tree.ts` を直さない）

## 前提と制約

分類: LIST, PERM

- **名前の決めは `07_functional/段10-F9/土台-knowledge.md`（1.4・3.1・5）が正本**。契約・共通の部品（`reply.ts`・`shelf.ts`・`shape.ts` の `treeMark`・`PagePlace`・`TreeNode` の型）は K-675 が置いた物を使う（変えない）
- **口は読むだけ**。1 つの取引（`withTenant`）の中で読み、DB に書かない・お知らせも AI も呼ばない。ログに題名・フォルダの名前を出さない
- **棚の決め（土台 0 章）**：会社＝`app.kn_company_scope()` の 1 グループ・`is_personal = false`／グループ＝`app.kn_my_groups()`（自分の入っているグループ・会社のいちばん上は含まない）の各 id・`is_personal = false`／自分＝`is_personal = true` かつ持ち主が自分。**管理者でも、入っていないグループの棚は出ない**
- **読む文は 2 つ（フォルダとページ）**。どちらも `tenant_id = app.tenant_id()`・消していない物だけ・棚の条件（会社・入っているグループ・自分の持ち主）で絞り、行の守りがさらに見える物だけに絞る。ページは `state in ('draft', 'published')` だけ（前の形の `archived` は出さない）で、下書き（`state = 'draft'`）は持ち主だけ。**行ごとに関数を呼ばない**（5,000 行で関数を 5,000 回呼ぶと遅い。棚と持ち主の等号で絞り、見える・見えないは行の守りに任せる）
- **並び**：同じ親の中は フォルダ → ページ、それぞれ `position`・名前（題名）・id の順。名前・題名の比べは `collate "C"`（文字コード順・どの DB の設定でも同じ並び）。棚の直下のフォルダ・ページも同じ
- **木の大きさ**：フォルダとページを合わせて **5,000 ノードまで**（フォルダを先に・残りがページ）。切ったら `truncated: true` とログに `[knowledge] 木を 5000 で切った` を 1 行（題名・名前は出さない）。読む文は各 5,001 行で止める。親のフォルダが切れて見つからないフォルダ・ページは棚の直下に出す（消さない）
- **ページの印（`mark`・1 つだけ）**：承認待ち（`waiting`）＞断られて帯を消していない（`declined`）＞下書き（`draft`）＞写し（`copy`・`copied_from_page_id` がある）＞なし（null）。選ぶ関数は K-675 の `treeMark({ draft, waiting, declined, copied })`。`must` は `is_must`
- **書ける棚（`can_write`）**：会社＝`app.kn_shelf_writable(会社のいちばん上, false, null)`（管理者だけ）／`group_ids`＝入っているグループのうち `kn_shelf_writable` が真の物（そのグループのマネージャー）／`me`＝いつも true。権限は呼ぶたびに今の所属で決める（外された直後・付けた直後も入り直さず効く）
- **管理の数（`admin_counts`）**：管理者（`app.is_admin(今の人)`）か、どれかのグループのマネージャー（`app.kn_group_manager`）には `{ approvals, review }`、それ以外（メンバー・閲覧のみ・どこにも入っていない人）は null。数は後ろの葉の関数が出す（下）。**この葉の間は 0・0**
- **グループの色（`tone`）**：会社の中で、会社のいちばん上でないグループを作った順（`created_at`・id）に 0 から数えた番号を 3 で割った余りで teal・plum・amber（人ごとに変わらない）。`id` はグループの uuid・`code` は札の字に使うグループのチケットの番号の頭（`scopes.ticket_prefix`・`nullif(ticket_prefix, '')`・決めていないグループは null）・`shared` は false（共有された物だけのグループは後ろの葉）
- **会社の名前**：`tenants.name`（今の会社）。複数の会社に入っている人は会社ごとに別の人（member）なので、今の会社の木だけが返る（切り替えは文脈が替わるだけ・新しい仕組みは足さない）
- **後ろの葉が作る表に頼る 4 つ（関数のファイルを分ける）**：次の表のとおり、この葉が「無いときの形」で置き、持ち主の葉が中身を差し替える。`tree.ts` は 4 つを呼ぶだけで、後ろの葉は `tree.ts` を直さない
