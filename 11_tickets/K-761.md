## 目的

PC（Bridge）が仕事の間に呼ぶ契約の口 2 本を作る（今はどちらも契約だけで 501）。Bridge の呼び先も契約の道に替える。

- `reportBrowserState`（POST /api/v1/bridge/jobs/:id/browser・体は `{ browser, state }`）：その仕事で AI が使うブラウザ（`chrome`＝本人の Chrome／`dedicated`＝Bridge 専用）の**様子**を、仕事の出来事（bridge_job_events・種類 `browser`）に残す。様子は `using`（使う仕事として始めた）と `off`（使えなかった）の 2 つ。**写真・画面の写しは作らない**（送らない・残さない。契約の「触る表」から attachments を外す）。画面（`work` の 1 行）には出さない：使えなかったことは前から会話の 1 行（`notice`）で出ており、同じことを二重に出さない
- `getFileForBridge`（GET /api/v1/bridge/files/:ref?job_id=<仕事の id>・`:ref` は資料の id）：その仕事に**付いた資料**の、期限つきの署名 URL を返す（`{ url, name, mime, size }`）。前の道すじ `POST /api/auth-ext/bridge/attachment`（agent.ts）の中身を移す。付いていない物・ほかの仕事の物・消した物は 404。**資料を付ける口は作らない**（D-153.16）ので、新しい道では付く物が無い（前の道すじで付けた物と試験だけが対象）。署名 URL を受ける所 `GET /api/auth-ext/files/:ref`（署名と期限だけで判定）はそのまま使う

Bridge の側：資料を取りに行く呼び先を新しい口へ替え、ブラウザを使う仕事では仕事の始めに `using`・使えなかったとき（`onBrowserOff`）に `off` を送る。

## 前提と制約

分類: PERM, FILE

- **migration は 1 本**（番号−600＝161 分 → 02:41 → `packages/db/migrations/20261125024100_job_browser_file.sql`）。列・表は足さない。①仕事の出来事の種類の check（`bridge_job_events_kind_check`・0056 の 15 種）に `browser` を足して作り直す（**15 種を全部写して 1 つ足す**。ほかの葉が同じ check を作り直すなら、入れる順の後の方が前の分を含めて作る）②`app.bridge_browser_report(p_session uuid, p_job uuid, p_browser text, p_state text) returns jsonb`③`app.bridge_job_file(p_session uuid, p_job uuid, p_ref uuid) returns jsonb`。関数は `security definer`・`set search_path = public, app, pg_temp`・public から外し `kaname_app` に渡す
- **その仕事を受け取った PC だけ**（D-128.163）：`app.bridge_job_of(p_session, p_job)`（0092）で仕事を引く。ほかの PC・ほかの人・ほかの会社の PC・無い仕事は 404。さらに**動いている仕事（running・asking）だけ**（終わった・待っている仕事は 404）
- **app.bridge_browser_report**：`p_browser` が chrome・dedicated、`p_state` が using・off 以外なら `{error:'bad_value'}`（口が先に 422 にする・2 層目）。仕事の行を `for update` で取り、同じ仕事に**同じ（browser, state）の出来事が既にあれば書かず** `{ok:true, recorded:false}`（二重送信・同時の 2 つでも 1 行）、無ければ `bridge_job_events`（kind `browser`・seq 0・payload は `{browser, state}` だけ）に 1 行書いて `{ok:true, recorded:true}`。動いていない・受け取っていない仕事は `{error:'not_found'}`。会話にも証跡にもお知らせにも書かない
- **app.bridge_job_file**：仕事の `attachment_ids` に在り、`attachments.deleted_at` が空の資料だけ。答え `{storage_ref, name, mime, size, tenant_id, member_id}`（`member_id` は仕事の持ち主＝署名の証跡の主語）。無ければ null（口が 404）。前の `app.bridge_attachment`（0042）に「消した資料を除く」を足した形（前の道すじが使い続けるので、0042 の関数は直さない。消すのは K-765）
- **入力の形の確かめは口が自分でやる**（入口の zod は全部 optional）：`reportBrowserState` は `browser`・`state` が文字で決まった値のどちらか（無い・外の値・文字でないは 422・欄名つき）。`getFileForBridge` は `ref` が uuid・`job_id`（問い合わせ）が uuid（どちらも無い・形違いは 422・欄 ref／job_id）。知らない項目は入口の strict が 422
- **断る番号**（控え帳）：404＝付いていない・ほかの仕事・動いていない・無い・消した（NOT_FOUND・欄・details を付けない）／422＝契約に書ける形の誤りだけ／502＝置き場が署名 URL を出せない（**E-TALK-040**・置き場の鍵・署名の鍵を答えにもログにも出さない）／DB の失敗は 503・E-PAGE-003。409 は無い。PC の印が無い・外した PC は入口が 401
- 契約の「問い合わせ」：`getFileForBridge` は `QUERIES` に `["job_id"]` を足す。道の値 `:ref` は名前が id で終わらないので、契約の道の値の形に uuid の pattern を書く（`PATH_PATTERNS`・K-144 ⑲＝口が値域つきで断る）
- 関門の宣言は [C2, C3, C4, C5]。この葉が使うのは C2（出来事の書き込み）と C4（資料の署名 URL を出す置き場の関門）。C3・C5 は契約の `reportBrowserState` が行為の裏側から持つ関門で、宣言だけ合わせる（KC4：apis の口の関門を全部書く）。この葉はモデルもプロセスも呼ばない。署名 URL を出したことは関門 C4（`ObjectStore.signUrl`）が証跡 `object.sign` に残す（誰に出したか＝仕事の持ち主）。ネットワーク・モデル・プロセス・通知は無い。材料は `d.appPool`・`d.objects`・`d.config.baseUrl`
- 送る量・uuid・上限の入口の共通の確かめ（K-144）と同意し直しの止め（K-53）はそのまま
