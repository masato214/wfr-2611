## 目的

詳細の項目の表の「確認項目」の行（画面は K-450）の「チェックを付ける・外す」「文を直す」「行を外す」が呼ぶ契約の口 2 本を作る（今はどちらも 501）：
`updateTestSpec`（PATCH /api/v1/test_specs/:id）と `deleteTestSpec`（DELETE /api/v1/test_specs/:id・論理削除）。あわせて、機械・AI がチェックを付ける道を DB の関数 `app.test_spec_check_by_ai` として**用意だけする**（呼ぶのは検査を流す段・段 6。口は作らない）。

- **チェックを付ける・外す**：入力は `checked`（true／false）。付ける＝`checked_at = now()` と `checked_by_member_id`（付けた人＝呼んだ人）。外す＝`checked_at`・`checked_by_member_id`・`checked_by_ai` を空に戻す。そのチケットを直せる人なら誰でもできる（D-150.56）
- **文を直す**：入力は `title`。**直せるのはチェックが付いていない間だけ**（D-150.55）。付いた行の文を直すと 409・E-SPEC-021（外してから直す）。`knowledge` の行は、チェックが付いていなくても 409・E-SPEC-022（下の「出どころの扱い」）。文は足すときと同じ決まり（前後の空白を落として 1〜200 字・K-434 の `app.test_spec_title_check`）
- **入力は `checked` か `title` のどちらか 1 つと `version`**。両方・どちらも無いは契約の oneOf で 422。`version` が今の版と違えば 409・E-SPEC-020（先に変えられた・行は変わらない）。何かが変わったときだけ版が +1。同じ値（付いている行に付ける・同じ文）は 200 で版も更新時刻もやり取りも証跡も動かない
- **行を外す**（`deleteTestSpec`）：`deleted_at` を入れる論理削除。行も確かめの結果（`checks`）も残る。体も版も受けない。もう外した行・無い行は 404。`knowledge` の行は 409・E-SPEC-022
- **どの操作も、同じ取引でやり取りに 1 行**（`ticket_messages` の kind `change`・D-150.40・D-128.45）：「〈名前〉が確認項目『〈文〉』にチェックを付けました／のチェックを外しました／を直しました／を外しました」。人が操作したので `author_member_id`＝その人。機械・AI の道は author が空で名前は「AI」。記録の表は別に作らない。書く所は K-434 の `app.test_spec_log` の 1 か所（最初から 5 引数の最終の形・K-435 は作り直さない）
- **完了したチケットでは、付ける・外す・直す・外すのどれもできない**（409・E-SPEC-001＝K-434 が決めた番号・D-150.33・D-150.56。確認の結果が項目を指すので、完了後に変えると結果の根拠が変わる）。消されたチケットは 404
- **出どころ（`source`）の扱い**（勧めを変えた 2026-11-22・段 10 の代表の決め「必ず守るは写しても上が効く」に合わせる）：`knowledge`（ナレッジの「必ず守る」から入った行）は、**人は文を直せない・行を外せない**（409・E-SPEC-022・欄なし）。**チェックの付け外しはできる**。`manual`・`ai` の行は同じ扱い（付ける・直す・外す）。機械・AI が外す道（DB の関数）はこの口の話ではなく、この葉は作らない（段 10 か AI の段）

読む・足すは K-434、作るとき `specs[]` から足すは K-437、使わない理由は K-565、画面は K-450。

## 前提と制約

分類: CRUD, PERM

- **口は 2 本とも新しい専用の入力・答え**。直す入力は `version`（必須・1 以上の整数）と `checked`（真偽）か `title`（文）のどちらか 1 つ（strict）。`ticket_id`・id・tenant_id・source・source_ref_id・チェックの列・種類・判定の型・設定値・off_reason・deleted_at・知らない欄は 422。**答えは K-434 と同じ `SpecItem = { id, title, checked, position, source, version }`**（鍵ちょうど 6。`version` は直したあとの行の版）。消す答えは外す前の姿（position は外す前の番号）
- **断る番号**（控え帳：422＝契約に書ける形の誤りだけ／404＝無い・見えない／409＝今の状態ではできない／検査の例外は足さない）：形の誤りは番号なしの **422・VALIDATION_ERROR**（欄は version・checked・title）／無い・消した行・見えない・別の会社・消されたチケットは **404**／書けない人は入口の **403**／版が違う **409・E-SPEC-020**／チェックが付いている行の文は **409・E-SPEC-021**／ナレッジから入った行（`knowledge`）の文の直しと行を外すは **409・E-SPEC-022**／完了したチケットは **409・E-SPEC-001**（K-434 の `errors.d/K-434.json`。この葉は番号を足さずに使う）。置き場は `errors.d/K-435.json`（E-SPEC-020〜039 の枠。この葉は 020・021・022 を使う）
- **404・409 の答えの体は `{ error, code }` だけ**（控え帳 2026-11-21 01:15 K-385・2026-11-20 20:50 K-401：`field`・`details`・`detail` を付けない）。入口の 404（見えない・別の会社・無い uuid）も同じ形。422 だけが `details` を持つ
- **404 の出どころ**：見えない人・別の会社・無い uuid の 404 は、入口（`op.ts` の行の確かめ）が先に `{error:"not_found",code:"NOT_FOUND"}` で返す。この葉の口・関数が返す 404 は、入口では見える物（消した行・消されたチケット）だけ
- **422 は全部、契約に書く**（`UNEXPRESSIBLE_422` は空）：版は 1 以上／`checked` は真偽／`title` は空白だけでない 1〜200 字／`checked` か `title` のどちらか 1 つ（`INPUT_RULES` の oneOf）。入口の zod は値域の言葉を読まないので、**題名の確かめは K-434 の `app.test_spec_title_check` が 1 か所で持つ**（直す関数が最初に呼び、外れなら欄 `title` の 422）。契約の値域は関数が受ける集合より狭く書かない
- **順**：入口（401・行の守りの 403・404）→ 形（422）→ 状態（完了 409・E-SPEC-001）→ 版（409・E-SPEC-020）→ 文なら「同じ文なら何も変えない」→ チェックが付いていれば 409・E-SPEC-021（`knowledge` の行は、文の直しも行を外すも、版の確かめの後・同じ文の確かめの前に 409・E-SPEC-022。行を外すは完了・見えるかの確かめの後）。入力が外れていれば、チケットの状態に関わらず 422
- **版**：何かが変わったときだけ +1（付ける・外す・文を直すのどれも）。同じ版で同時に 2 本来たら 1 本だけ通る（行を `for update` で取ってから版を比べる）。消すは版を見ない・変えない
- **同時の完了**：直す・外すは、チケットの行を `for share`・確認項目の行を `for update` の順で取る（K-434 の足すと同じ順。完了の確定 `app.ticket_complete` の `for update` と順番にする）。完了の後に来た方は 409・E-SPEC-001
- **やり取りの 1 行の形**（`app.test_spec_log` の 1 か所・名前は `app.member_name`・AI は author が空で名前は「AI 」＝「AI が確認項目…」と AI の後に空白を 1 つ置く（K435-DB-001・002）。K-435 の migration が K-434 の同じ関数を、この 1 点だけ直して作り直す）：
  - 付ける「〈名前〉が確認項目『〈文〉』にチェックを付けました」・changes `[{field: "test_spec", from: false, to: true, note: 〈文〉}]`（どの行も note に確認項目の文を入れる）
  - 外す「〈名前〉が確認項目『〈文〉』のチェックを外しました」・`from: true, to: false, note: 〈文〉`
  - 直す「〈名前〉が確認項目『〈新しい文〉』を直しました」・`from: 前の文, to: 新しい文, note: 新しい文`
  - 外す（行）「〈名前〉が確認項目『〈文〉』を外しました」・`from: 文, to: null, note: 文`
  - 足す（K-434）「〈名前〉が確認項目を足しました：〈文〉」はそのまま
- **証跡**（`audit_events`・C2）：直す＝`test_spec.update`（target_type test_specs・target_id 行の id・payload `{ticket_id, changed: ["checked"] か ["title"]}`）・外す＝`test_spec.delete`（payload `{ticket_id}`）・AI の道＝`test_spec.check_ai`（payload `{ticket_id, checked}`）。題名の文は入れない。何も変わらなかったときは書かない
- **DB の守り**：K-434 の守り 3 つ（時刻なしで付けた人は不可・人と AI の両方は不可・出どころ 3 つ）に任せる。口の前の確かめ（契約）と DB の関数と DB の守りの 3 層（付ける・外すは関数が列をそろえて書くので、口を通らない書き込みは K-434 の K434-API-017 が止める）
- **機械・AI の道**（DB の関数 `app.test_spec_check_by_ai`）：口は作らない。呼ぶのは検査を流す段（段 6）。人の文脈を要らず、会社の文脈だけで動く（`app.tenant_id()` が無ければ not_found）。付けた人（member）は空・`checked_by_ai` を true に。やり取りは author が空で名前は「AI」
- 外へ出ない：メールも知らせ（受け箱の行・関門 C6）も出さない（チェックを付け外しても誰にも知らせない。やり取りの 1 行は流れに載るだけ）。AI も PC も呼ばない
- ログに題名の文を出さない（行の id と例外の種類だけ）
- 業務の型は無くした（D-150.60・本線に残る分は K-582 が外す）。この葉は依存に持たない
