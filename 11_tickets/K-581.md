## 目的

作る口 `createTicket`（K-437 が新しい形にした）に、**作るときにつなぐ相手 `links`** を足す。作る面（K-580）が「＋ つながりを足す」で選んだ相手を、チケットと同じ 1 つの取引でつなぐ（途中で断られても、半端なチケットもつながりも残らない）。

- 入力 `links`（任意）：`[{ kind: "related" | "derived_from", other_ticket_id: uuid }]`・0〜20 件・同じ組は重ねない。送るのは足した相手だけ（番号・題名・段の字は送らない）
- 書く先：新しいチケットから相手への `ticket_links` の行（関連は 1 行・派生元は「新しいチケット → 相手」の向き）と、証跡 `ticket_link.create` を 1 件ずつ。**書くのも確かめるのも K-441 の `app.ticket_link_add` の 1 本**（見えるか → 書けるか → つなぐ → 証跡の順）。作る関数の中に確かめと証跡を別に持たない（`app.ticket_link_put` を直に呼ばない・L-002）
- 断り：相手が無い・消した・見えない・別の会社は 404・E-PAGE-001（欄なし）／相手に書けないは 403・FORBIDDEN（欄なし）／形の誤りは 422（欄 `links`・`links.<番号>`）。知らせとやり取りの行は作らない（つながりは欄の変更ではない・D-128.45）

本文・項目・確認項目の書き込みと、それらの断りの番号は K-437。複製が写すつながりは K-438（`app.ticket_link_put` を自分の関数から呼ぶ）。作る面の見た目と送る前の手元の確かめは K-580。

## 前提と制約

分類: CRUD, PERM

- **入力の形**：契約が `maxItems: 20`・`uniqueItems: true`・要素は `{ kind: "related" | "derived_from", other_ticket_id: uuid }` の 2 鍵だけ（知らない鍵なし）を持つ。21 件・同じ組 2 回・知らない鍵・種類違い・uuid でない相手は 422・欄 `links…`（契約が先に断る。口の `checkLinks`（`payload.ts`）は同じ形を確かめる最後の砦）。`links` が無い・空の並びは今までどおり（つながり 0）
- **呼び方**：`app.ticket_create`（K-437 の migration の版）の中で、確認項目を書いた後・受け箱の前に、`links` を並びの順に 1 件ずつ `app.ticket_link_add(新しいチケットの id, jsonb_build_object('other_ticket_id', 相手, 'kind', 種類))`（K-441）を呼ぶ。この関数が **新しいチケットが見えて書けるか → 相手が見えるか → 相手に書けるか → `app.ticket_link_put`（同じ会社・消していない・自分自身でない・重複・派生元の輪）→ 証跡 `ticket_link.create`** をこの順で 1 か所で持つ。作る関数は答えを振り分けるだけ。作る人はグループに書けるのでチケットが見えて書ける
- **答えの振り分け**（K-441 の答えの言葉 → 作る関数の答え）：`ok` → 次の 1 件へ／`not_found`・`gone`（相手が無い・消した・見えない・別の会社）→ `{ok:false, status:404, code:'LINK_GONE'}`／`not_writable`（相手に書けない）→ `{ok:false, status:403, code:'LINK_FORBIDDEN'}`／`not_member` → 403・`LINK_FORBIDDEN`（作るの手前で止まるので届かない最後の砦）。**`same`・`duplicate`・`cycle`・`bad_kind` は新しいチケットでは起きない**（相手の id は新しい id と等しくならない・同じ組は契約が先に 422・新しいチケットは誰の派生元でもないので輪にならない・種類は契約が確かめる）。**既定の答えは置かない**：知らない言葉・起きないはずの言葉は例外にして取引ごと戻す（口は 503・E-PAGE-003）。E-LNK-001〜003 は作る口では出さない
- 口が `LINK_GONE` を 404・`E-PAGE-001`（欄・details・detail なし）、`LINK_FORBIDDEN` を 403・`FORBIDDEN`（欄なし）に振る。K-437 の `gone(code)` と同じ体（`error`・`code`・`message`・`action`・`undo`・`support_code` だけ）。422 だけ `details` を持つ
- 証跡：1 件ずつ `ticket_link.create`（target_type ticket_links・target_id 行の id・payload は `ticket_id`・`other_ticket_id`・`kind` の 3 鍵だけ。題名・本文は入れない）。**作る証跡には含めない**（作る口は証跡を書かない・K-60 のまま）。知らせ・やり取りの行（kind `change`）は作らない
- **1 つの取引**：つなぐ所で落ちれば、チケット・本文・項目の値・確認項目・つながり・証跡・受け箱の行が全部戻る（口は 503・E-PAGE-003）。断り（404・403）も同じ取引で戻るので何も残らない
- 相手が選べるかは、書いている間に変わる（相手が消された・見えなくなった・グループが読むだけになった）ので、口の入口では確かめず、書くときに関数が確かめる
- 外には何も出さない（C1 を通らない・メールなし・PC をつながなくても作れる D-127.8）。ログに相手の題名・番号を出さない
