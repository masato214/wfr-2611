## 目的

詳細の項目の表（画面は K-569）で、会社が足した項目（7 つの型）の値を入れる・直す・空にするときに呼ぶ契約の口 `updateTicket`（PATCH /api/v1/tickets/:id）に、**会社の項目の値の組**を 1 つ足す。口と「欄ごとの処理の表」（`TICKET_FIELD_GROUPS`）は段 7 の K-387・K-440 が作る。この葉は、その表に組を **1 つ**（`ticketFields`）足すだけで、口は新しく作らない（`apis: []`・口の登録先は K-387 の物）。表と読む口は K-563、作るとき `fields` を書くのは K-437。

- **入力**は体の `fields`（`{ "<項目の id>": 値 }`。送った項目だけ変える）。値の形は型ごと：短い文字・長い文章＝文字／数＝数／日付＝`YYYY-MM-DD` の文字／1 つ選ぶ＝選択肢の id／複数選ぶ＝選択肢の id の並び／チェック＝true・false。**空にするのは null**（空の文字・空白だけ・空の並びも「空にする」と同じに扱う）
- **断る**：契約に書ける形の誤り（`fields` が object でない・空・鍵が uuid でない・値が文字・数・真偽・文字の並び・null のどれでもない・NUL）は **422・欄 `fields`**。**マスタ（DB）で決まる断りは 404／409（体は `{ error, code }` だけ）**：無い・消した・別の会社の項目は **404・E-PAGE-001**／その種別に出ない項目は **409・E-FLD-001**／選択肢に無い値は **409・E-FLD-002**／項目の型と合わない値は **409・E-FLD-003**／必須の項目を空にする（必須のチェックは false・null も同じ）は **409・E-FLD-004**（D-150.51）
- **会社が必須にした項目は、作った後も空にできない**（E-FLD-004）。ただしマスタが後から必須になったときの、もともと空のチケットは、その項目を送らない限り別の項目を直せる（前からあるチケットには効かず、次にその項目を直すときに効く）
- **1 回の要求は全部通るか全部戻る**。同じ要求の別の組（優先度・親・段・実績・保留）の欄が断られたら `fields` も書かない／`fields` が断られたら別の組も書かない（K-440 の振り分けが同じ取引で組を順に呼び、どれかが断ったら戻す）
- **変えたら、同じ取引でやり取りに 1 行**（`ticket_messages` の kind `change`・1 回の要求に 1 行）：「〈名前〉が〈項目の名前〉を A → B に変えました」（D-150.40・D-128.45）。同じ値なら何も書かない（`changed: false`・行も更新時刻もやり取りも証跡も知らせも動かない）
- **担当者でない人が変えたときは、担当者の受け箱に知らせる**（D-150.32・自分で変えたら知らせない・担当者がいないか抜けた・止められた人なら知らせない）。1 回の要求は 1 通。メールは出さない
- **完了したチケットでも変えられる**（K-387 の実績・K-440 の優先度と親と同じ。段を変えるのだけが完了後は 409。下の「代表に聞くこと」）

マスタを作る・直す口と画面は段 10、確認項目は K-434・K-435、作るとき書くのは K-437、読む口 `getTicket` の `fields` は K-560。
