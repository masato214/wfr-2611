## 前提と制約

分類: CRUD, PERM

- **口は 3 本**。直す PATCH /ticket-fields/:id・消す DELETE /ticket-fields/:id・並べる POST /ticket-fields/order（PUT の前例が契約に 0 件のため POST）。権限は `custom_fields` の edit。上限は書く口 30/分/人
- **入力の形（契約に書く＝422）**：直す＝`name`・`field_type`・`required`・`description`・`options`・`kind_ids` のうち 1 つ以上（空の体は 422）。形の決まりは K-706 の足すと同じ（`name` の長さ・NUL・`kind_ids` は 1 つ以上の uuid・`options` の oneOf：`field_type` を送るときは選ぶ型なら選ぶ物が 1 つ以上要る）。`options` だけを送るときの「選ぶ物が 1 つ以上」も契約（minItems）で書き、空の並びは 422。並べる＝`field_ids`（uuid の並び・1 つ以上）
- **断る番号**（土台-settings.md の 3 章）：同じ名前に直す 409 E-FMS-001（K-706 の登録）／同じ名前の選ぶ物 409 E-FMS-004（K-706 の登録）／値が 1 つでも入っているのに型を変える 409 E-FMS-002／並びが今と合わない 409 E-FMS-003／選ぶ型でない項目に選ぶ物だけを送る 409 E-FMS-005／無い・消した・別の会社の項目・種別・選択肢の id 404 E-PAGE-001（欄・details なし）／権限なし 403／ログインなし 401／上限 429／DB の失敗 503 E-PAGE-003
- **直すとき**：送った欄だけ変える。`kind_ids` を送れば K-706 の `app.ticket_field_kinds_set` で種別の行を入れ替える（外した種別の行に `deleted_at`・足した種別の行を入れる・組が同じ行は残す）。選ぶ物は K-706 の `app.ticket_field_options_build` で組み立てる：送った並びが新しい並び・`id` を付けた物は同じ選択肢のまま名前を直す（値が持つ選択肢の id は変わらない）・付けない物は新しい選択肢・送らなかった物は外れる（外した選択肢を持つ既存の値は残る。値を書く口が以後その選択肢を断る）・今に無い id は 404。`field_type` は、値が 0 件ならどの型にも変えられ（選ぶ型 → ほかの型は選ぶ物を消す・ほかの型 → 選ぶ型は選ぶ物を一緒に送る）、1 件でも在れば同じ型だけ（違えば 409 E-FMS-002・何も変えない）。値の数は消していない `ticket_field_values` の行（消したチケットの物も）
- **消すとき**：`deleted_at` を入れる（項目の行・種別の行・値の行は残す＝見えなくなるだけ。値の行を消さないので、同じ名前で作り直しても前の値は戻らない＝新しい項目の id になる）。値が入っていても消せる。名前は消した後なら使い回せる。**消すと値が見えなくなることの確かめは画面の小窓（K-709）が持つ**
- **並べる**：`field_ids` が今の生きている項目の全部と過不足なく一致するときだけ（足りない・余る・重なる・消した項目・別の会社の項目は 409 E-FMS-003・何も変えない）。並びは渡した順に 10 刻み。答えは全部の項目
- 外へ出ない：メールもお知らせも出さない。AI も PC も呼ばない
- ログに項目の名前・説明・選ぶ物を出さない
- **共有の試験 `k144-contract.test.ts` をこの葉は変えない**（運ぶのは葉のファイル `k144.d/K-717.ts` だけ）
- **生成の試験は切る段の枝に無い**。**作る段の最初に**、契約の断片（`05_flow/screen_api.d/K-717.py`・`scripts/ci/contract_shape.d/K-717.py`）を足して作り手（`python3 scripts/ci/build_registries.py && python3 scripts/tickets/regen_all.py`）で生成の試験を作り、**実装より先に 1 つのコミットにする**（その後は変えない）。**先の葉の契約を前提にした前からの試験は、この葉の carry に入れない**
