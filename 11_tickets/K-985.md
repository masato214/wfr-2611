## 目的

運営の人の画面（K-986・下絵 op-team・op-team-add）が読む口と、運営の人を足す口を作る（行為 A134・今は 501）。運営の入口に外から作れる道は開けない（D-156.22）：足せるのは「運営の人」を持つ運営の人だけで、足された人はメールのリンクで自分のパスキーを付けてから入る（K-945 のリンクと画面 K-1003 をそのまま使う）。

- **listOpsMembers**（ops:ops_people）：生きている運営の人の一覧。1 行は 8 欄（下の「画面が使う答えの形」）。自分の行と、「運営の人」「値段を決める」の最後の 1 人の印を返し、画面が「変える」「外す」を押せない形にできる（D-156.34）
- **addOpsMember**（ops:ops_people・本人確認の取り直し）：メールとできること 1〜9 つ。新しい人は認証の部品の利用者（パスワードなし・確認済み）＋運営の会社の members＋ops_members を作り、パスキーを付けるリンク（24 時間・1 回）をメールで送る。**外した運営の人のメールなら、同じ人として足し直す**（パスキーを無くしたときの手順・D-156.22）
- できることを変える・外すは K-1009（この葉から分けた）。外すときに担当の問い合わせの担当を空にするのも K-1009（K1009-API-005）

  - どの道でも、その人の使っていないリンクを使えなくして（`used_at = now()`）、新しいリンクを 1 行（K-945 の `ops_setup_links`・24 時間）

- **名前は入るときに本人が付ける**（代表の答え 2026-11-23・D-156.66：足す小窓に名前の欄は置かない）：足すときの `display_name` はメールの @ の前（仮の名前）。届いたリンクで入るとき、本人が名前を付ける。リンクの口 `startOpsSetup`（K-945）の入力に `name`（前後の空白を落として 1〜40 字・空白だけは VALUE_RANGES の pattern `\S` で 422＝D-156.38 と同じ形・任意＝送らなければ名前は変えない）を足す（K-945 の断片 `05_flow/screen_api.d/K-945.py` の INPUTS・VALUE_RANGES に 1 つずつ・この葉が直す）。`features/F12/ops-setup/setup.ts` は、リンクが使えたときだけ、同じ取引で運営の会社の `members.display_name` を送られた名前にする（使えないリンクでは書かない）。名前の欄の画面は K-1003（/ops/setup）
- **メール**（関門 C6・`features/F12/ops/team-mail.ts`）：取引を閉じてから、`@kaname/notify` の `NotifyGateway`（transport は材料の `mailer`・`channelsOf` は email だけ）で 1 通。件名「【Kaname】運営の場所に招待されました」・本文にリンク（24 時間・1 回だけ・パスキーを付けてから入る旨）。印を件名に書かない。送れなくても運営の人は残し、201 の `meta.mail_sent` を false にする。ログは `console.error("[ops-team] 招待のメールを送れなかった")` だけ（宛先・印を出さない）

### 関数（migration `20261128012500_ops_team.sql`・K-985 → 85 分）

- `app.ops_member_row(p_ops_member uuid) returns jsonb`（security definer・stable・ops_require('any') を頭で呼ぶ）：上の 8 欄。`has_passkey` は `kaname_auth.passkey` に `"userId"` = その人の `auth_user_id` の行が在るか。`locked_caps` は ops_people・plan_decide のそれぞれで、生きている運営の人のうちその印を持つのがこの人だけか（K-1009 も同じ式を使う・1 か所）
