## 目的

段 5 の K-581（鎖の手前）を `flow.py start K-581 --cut c/段5` で始めると、持ち込みの台本 `scripts/tickets/cut_take.py` が共有の試験 `apps/api/test/features/contract/k144-contract.test.ts` で「本線の後からの変更とぶつかる」と止まる（followups.md の K-581 の行）。

原因：台本は共有の試験を 3 方で合わせるとき、元の版を「切る段の枝と本線の分かれ目」にしている。K-581 の重ねた元 K-437 は分かれ目の後に本線へ入り、切る段の版では K-437 の行のすぐ下に K-581 の行がある。分かれ目から見ると、本線は「K-437 の行を足した」、切る段は「K-437 の行と K-581 の行を足した」になり、同じ所を別々に変えたとして git merge-file がぶつかる。中身は「本線の版に自分の行を足すだけ」で、本当のぶつかりではない。

PM の決め（作り方）：
1. 分かれ目を元にして合わせ、ぶつからなければ今のまま
2. ぶつかったときだけ、元の版を「切る段の版から自分の印（行の末尾の `// K-xxx` と範囲）を外した物」にして合わせ直す。これで差は自分の行だけになり、本線の版にそれを足す
3. 合わせ直すと、切る段で足した印の無い行（どのチケットの物でもない行）を本線が消したように見えて落ちることがある。そういう行があれば落とさずに止める。判定は、まだのチケットの印と範囲を外した後の切る段の版で見る（外した範囲の中身は数えない）。同じ字面の行（`});` など）を見落とさないよう、行ごとの数で比べる：切る段の版での数が、分かれ目の数と合わせた結果の数の大きい方を超える行を「落ちた」とする（空行は数えない）
4. 2 回目の合わせもぶつかれば、今までどおり止める

## リスクと懸念

- 合わせ直しは、ぶつかりの中身が「自分の行」だけのときに効く。重ねた元とは別の、まだ本線に入っていないほかのチケットの行とぶつかる形は、今までどおり止まる（切る段の枝に本線を取り込んでからやり直す）
- 重ねた元を本線に入れるときに、その行の字面を直していると（CT-005 の形）、2 回目の合わせもぶつかって止まる。K-581 の start が通るかはこれで決まる（止まれば切る段の枝に本線を取り込んで切り直す）
- c/段10 の K-712 の混ざり（followups.md）は同じ台本の類だが、形が違えばこの直しでは止まりが残る。始めるときに PM が確かめる
