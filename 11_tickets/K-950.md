## 目的

問い合わせの小窓（K-953）でファイル・画面の写しを付けるための 2 つを作る（D-156.26：1 つ 10MB・5 つまで・画像と PDF と zip・画面の写しは自動で撮らずファイルとして付ける）。

1. **上げる先を求める口** `uploadInquiryAttachment`（POST /api/v1/inquiries/attachments・今は 501）：名前・種類・大きさを受け、添付の行（まだ検査していない・置く参照を決めた）と 1 回だけ使える印を作り、関門 C4 が署名した**置き場の上げ先**と、**上げ終わりの受け口**を `{ id, upload_url, done_url, expires_at }` で返す（K-948 の形）
2. **上げ終わりの受け口** `POST /api/uploads/inquiry/:token/done`（契約の口の外・体なし）：置き場に置かれた物を関門 C4 で読み、**中身の頭が名乗った種類と合うか・大きさが名乗ったとおりか**を照らしてから、行に検査の済んだ印を入れる（D-156.11「検査してから受ける」）。合わなければ置き場の物を消して断る

**体は口を通さない**：口は Vercel の関数 1 本で動き（apps/api/vercel.json・D-097）、関数に送れる体は 4.5MB まで（超えると関数に届く前に 413）。だから 10MB の体は、ブラウザが置き場（S3 互換）へ署名つき URL で**直に PUT** する。口が受けるのは小さな JSON（求める）と体の無い POST（上げ終わり）だけ。署名には大きさ（content-length）と種類（content-type）を入れ、置き場が違う体を断る。付けるのは K-949（createInquiry）と K-952（postInquiryMessage）が、検査の済んだ添付の id で行う。

## 前提と制約

分類: FILE, PERM

- **生成の試験は作る段の最初に作る**：契約の断片（`05_flow/screen_api.d/K-950.py`・`scripts/ci/contract_shape.d/K-950.py`）を足して作り手（K-949 と同じ順）で生成の試験を作り、**実装より先に 1 つのコミットにする**。先の葉の契約を前提にした前からの試験は carry に入れない
- **入力の形（契約＝422）**は K-948 の断片が持つ（name 1〜200・content_type は image/png・image/jpeg・image/gif・image/webp・application/pdf・application/zip・size 1〜10485760・3 つとも必須）
- 名前は前後の空白を落とし、道の区切り（`/`・`\`）の最後の後ろだけを残す。残りが空なら「ファイル」（置き場の参照は名前を使わない＝`tenants/<会社>/<uuid>`）
- **印**：32 バイトの乱数を base64url（43 字）にした物。行には sha256 の 16 進だけを持つ（`attachments.upload_token_hash`）。期限は作ってから 10 分（`upload_expires_at`）。上げ終わりで受けたら印を消す（1 回だけ）。`done_url` は `${config.baseUrl}/api/uploads/inquiry/<印>/done`。印は upload_url に入れない
- **置く参照は求めるときに決める**：`refOf(<会社>, <添付の id>)`（`tenants/<会社>/<添付の id>`・名前を使わない）を `attachments.upload_ref` に持つ。受けたら `storage_ref` に写す
- **上げ先（関門 C4 に足す）**：`ObjectStore.presignPut(ctx, ref, { contentType, size, ttlSec: 600, localBase })` が `{ url, expiresAt }` を返し、証跡 `object.presign_put`（target 参照・choke_point C4・payload `{ size, mime }`）を書く。
  - 外の置き場（staging・本番の S3 互換・`StoreOptions.externalSigner` が在り `presignPut` を持つ）：`ExternalSigner.presignPut(key, { contentType, size, ttlSec })` を足す。`s3Presigner(client, endpoint, bucket)` が `PutObjectCommand({ Bucket, Key, ContentType, ContentLength })` を `getSignedUrl(..., { expiresIn, signableHeaders: new Set(["content-length", "content-type"]) })` で署名する（置き場が違う大きさ・種類の体を 403 で断る）。`server.ts` は `s3Presigner(s3c, endpoint, config.storage.bucket)` を渡す。置き場の CORS（ブラウザからの PUT）は環境の準備（K-1101 の頼み・申し送り）
  - 外の置き場の `presignPut` が無い（開発・試験・CI のローカルの置き場・`presignGet` だけの差し替え）：`localBase`（`${config.baseUrl}/api/uploads/local`）の下に、参照・種類・大きさ・期限を Kaname の鍵（`signingSecret`・今の get の署名と同じ HMAC）で署名した URL を出す。受けるのは `ObjectStore.acceptSignedPut(query, body, contentType)`（署名・期限・**体の大きさが署名の大きさと同じ**・種類が同じを確かめ、違えば 403。同じなら置く＝S3 と同じ振る舞い）。受け口 `PUT /api/uploads/local` は外の置き場が無いときだけ差す（本番には無い）
- **上げ終わりの確かめ**（`features/F12/inquiries/upload-route.ts`・`sniff.ts`）：① `app.inquiry_attachment_peek(<印の hash>)`（**鍵を取らない読み**・期限内・消していない・`storage_ref is null` の行の `{id, tenant_id, member_id, mime, size, upload_ref}`。ほかは **404**・欄・details なし）② 関門 C4 の `objects.get(<その会社と本人の文脈>, upload_ref)`（無ければ大きさ 0 として ③ へ）③ 置いた大きさが 10MB を超えれば **413 E-INQ-004**・名乗った大きさと違えば **400 E-INQ-004** ④ 頭のバイトが名乗った種類の決まった頭と合わなければ **415 E-INQ-003**（png `89 50 4E 47 0D 0A 1A 0A`・jpeg `FF D8 FF`・gif `GIF87a`／`GIF89a`・webp `RIFF....WEBP`・pdf `%PDF-`・zip `PK 03 04`／`PK 05 06`）。③④ で断るときは置き場の物を `objects.delete` で消す ⑤ **1 つの取引**（始めて・終える）：`app.inquiry_attachment_take(<印の hash>)`（`for update skip locked`・null なら同時の 2 回目＝**404**・置き場の物は消さない）→ `app.inquiry_attachment_done(id, upload_ref, size)`（`storage_ref`・`size`・`scanned_at now()` を入れ印を消し、証跡 `inquiry_attachment.put`・target_type `attachments`・target_id 添付の id・choke_point_id `C4`・payload `{size, mime}`）→ commit。⑤ が落ちたら置き場の物を消して **503 E-PAGE-003**（後片付け）。答え 200 `{ data: { id, size } }`
- **DB の接続と鍵を持つのは ⑤ の 1 取引だけ**（置き場から読む ② の間は接続を持たない・G-16）。体を読む間に行の鍵を持たないので、遅い回線でも DB を占めない
- 受け口の番号は契約の口の外なので契約の言葉（422 の決まり）に縛られないが、断りの考え方は控え帳と同じ：無い・見えない＝404（何も漏らさない）・DB の失敗＝503 E-PAGE-003。中身の種類が違う＝415・大きさ＝400／413（ブラウザの決まりの番号）
- **関門の宣言** choke_points は契約の口と同じ [C2, C4, C6]（KC4）。求める口は C2・C4（上げ先の署名）、受け口は C2・C4。C6 は呼ばない
- **ウイルスなどの中身の検査はしない**（D-029「何でも受け取る・上限だけ」。この葉の「検査」は種類と大きさの照らし。運営が開くときは置き場の期限つき URL で落とす＝K-973）
- 受け口は CORS の許し（app.ts の `/api/*`）の下に置く：`apps/api/src/server.ts` で `app.route("/api/uploads", inquiryUploadRoute(hookDeps))` の 1 行。`inquiryUploadRoute` は上げ終わり（`POST /inquiry/:token/done`）と、外の置き場が無いときだけローカルの上げ先（`PUT /local`）を持つ。セッションは見ない（印だけで判定・`/files/:ref` と同じ）
- 断る番号（求める口）：先方の権限の人 403（入口）・ログインなし 401・上限 429（60/分/人）・DB の失敗 503 E-PAGE-003
- ログに名前・中身を出さない（会社の id・添付の id・例外の種類だけ）

### 表と関数（migration `20261128005000_inquiry_attachments.sql`・K-950 → 50 分）

- `attachments`：`upload_token_hash text`・`upload_expires_at timestamptz`・`upload_ref text`（一意の索引 `attachments_upload_token_uq on attachments (upload_token_hash) where upload_token_hash is not null`）
- `app.inquiry_attachment_start(p_name text, p_mime text, p_size bigint, p_token_hash text) returns jsonb`（security definer・会社の人の文脈）：`app.role() = 'member'`・`app.member_ok()` でなければ forbidden。行（会社・本人の層・`owner_type 'inquiry'`・`uploaded_by` 本人・`name`・`mime`・`size`・印・期限 `now() + interval '10 minutes'`・`upload_ref = 'tenants/<会社>/<id>'`）を作り `{"data":{id, upload_ref, expires_at}}`
- `app.inquiry_attachment_peek(p_token_hash text) returns jsonb`（security definer・stable・鍵を取らない）：期限内・消していない・`storage_ref is null` の行なら `{id, tenant_id, member_id, mime, size, upload_ref}`、ほかは null
- `app.inquiry_attachment_take(p_token_hash text) returns uuid`（security definer）：同じ条件の行を `for update skip locked` で引き、id を返す（同時の 2 回目は null）
- `app.inquiry_attachment_done(p_id uuid, p_ref text, p_size bigint) returns boolean`（security definer）：その行の `storage_ref`・`size`・`scanned_at` を入れ、印と期限を消す。証跡も中で書く
- 4 つとも `revoke all … from public`・`grant execute … to kaname_app`。`take` と `done` は受け口の同じ 1 取引で呼ぶ

## 外に影響する手順

1. DB に書く（求める口）：添付の行と印と置く参照を `app.inquiry_attachment_start` で作る［残る］— 失敗の行：K950-API-005（落ちたら行を作らない）。後片付け：使われずに期限が切れた行は残る（印が期限切れで使えず、問い合わせにも付けられない＝K-949 の検査前の 409）。消す仕組みは作らない（時間で動く仕組みは作らない・D-128.146 と同じ考え）
2. 関門 C4 で上げ先に署名する（証跡 `object.presign_put`）— 失敗の行：K950-UP-009（記録）。署名が作れないときは 503（行は 1 のまま期限で使えなくなる）
