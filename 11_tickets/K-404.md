## 目的

渡しが成り立った（受けた・申し出に渡した・配った）ときに、渡した人が選んだ「一緒に切り替えるもの」（D-125.70・D-148.11）を実際に移す DB の関数 `app.handover_apply_switch(p_handover, p_from, p_to)` を本物にする。
K-401 が空の形（'{}' を返すだけ）で作り、受けるの関数（K-403）・申し出に渡すの関数（K-408）・配るの関数（K-409・K-410）が同じ取引の中で呼ぶ。この葉は関数の中身だけを書く。

- 子・孫（3 段まで）：前の担当者（p_from）が担当で、まだ開いている物を新しい担当者（p_to）にする。ほかの人の物・完了した・消した物は移さない
- 関連・派生元（ticket_links の両向き）：同じ決め
- グループ：新しい担当者がチケットのグループにいないときだけ、チケットのグループを新しい担当者の主のグループにする。**番号は変えない**（D-125.60）
- 軸：段 9 では受けない（K-401 の切り替えの整えが axes を空にしか通さない・K-401 の代表に聞くこと 1）。数は 0
- 答え：実際に移した物 `{ "children": int, "links": int, "group": { "from": uuid, "to": uuid } | null, "axes": 0 }`。呼んだ側が渡しの行の switch_applied に書く（K-412 の帯「子チケット 2 件も一緒に移りました ・ グループは営業のまま」）

「受けるを押すと切り替わる」の通し（口から）は中間テスト K-416 が持つ（切り方.md 3 章「9-A4 → 9-A3 は外した」）。この葉の試験は関数を直に呼ぶ。

## 前提と制約

分類: CRUD

- **移す物は K-401 の `app.handover_switch_targets(p_ticket, p_from)` だけを使う**（下見の数と移す物を 1 か所で決める＝下見に「子チケット 2 件も渡す」と出た 2 件がそのまま移る）。この葉で木の辿り方を書き直さない
- 切り替える物は渡しの行の switch（K-401 の app.handover_switch_normalize で整えた物）を読む。決まり（handover_rules）はこの関数では読み直さない（渡した時点の決めで動く）
- グループは、呼ばれた時点で p_to がチケットのグループにいない（`app.handover_in_group(p_to, scope)` が false）ときだけ移す。switch.group が true でも p_to がいれば移さない（守りの 2 層目：渡してから受けるまでの間に p_to がグループに入ったとき）。子・孫・関連のグループは移さない
- 呼ばれるのは、担当者を書き換えた後（K-403）。チケット自身は移す物に入らない（switch_targets はチケット自身を返さない）
- 無い渡し・別の会社の渡しなら例外（22023）を投げる（呼んだ側の取引ごと戻る）
- 書き換えた行の updated_by は app.user_id()（答えた人）
- kaname_app には渡さない（K-401 の決め・中だけで使う。呼ぶのは security definer の関数）
