## 目的

完了の口（`completeTicket`・DB の関数 `app.ticket_complete`）は、実施事項の区画（`todo`）の「- 」の行が全部済みでないと完了にできず（E-VAL-022）、完了のとき全部「- [x]」に書き換えていた。チケットの本文が自由な 1 枚の文書になる（D-150.35）ので、これを新しい決め（D-150.42）に直す。

1. **完了を止めない**：本文のチェックの箱（文書の木の `taskItem`）と確認項目の未チェックは、**数えて答えに返すだけ**。残っていても完了にできる。確かめる（止める）のは前からの 完了の条件の確かめ印（`conditions_confirmed`）・終わっていない子・段・走っている実行・承認待ちだけ
2. **完了で本文を書き換えない**：実施事項の区画も本文の行も、完了の前後で版・字・doc が同じ（前は実施事項を全部「- [x]」にして新しい版を足していた）
3. **入力 `todo_checked`・`todo_version`（実施事項の番号と版）は、契約に残して中身は見ない**：前の完了の小窓（画面の葉 K-572 が入るまで）は送り続けるので、**受けても落ちない形**にする。両方とも**任意**にし（無くても通る）、形の決まり（番号は 0 以上の整数の並び・版は 0 以上の整数）は契約のまま（形の誤りは 422）。E-VAL-022（残りの項目）・E-CONF-017（実施事項が変わった）・範囲の外の番号の断りは出さない。**契約から外すのは K-575**（画面の葉 K-572 が送らなくなった後）
4. **数え方**：本文の行（鍵 `body`・消していない）が在れば、文書の木の中の `taskItem` で `attrs.checked` が真偽の `true` でない物の数（入れ子も数える・`attrs` が無い・文字の `"true"`・null は未チェック・段落の字の「[ ]」は数えない）。本文の行が無いチケット（前の形・K-575 が移すまで）は、実施事項の区画の字の「- 」で始まる行のうち「- [x]」（大文字の X も）でない行の数。確認項目は `test_specs`（消していない）の `checked_at` が空の行の数。答えは `unchecked: { body, specs }`

画面が完了の前に未チェックを出すための**読む物**は、新しい口を足さずに決めた（下「前提と制約」）：本文の未チェックの行は `getTicket`（K-560）の `body.doc` から画面が数え、確認項目の未チェックの文は `listTestSpecs`（K-434）を「完了にする」を押したときに 1 回読む。

## 前提と制約

分類: CRUD, PERM

- 関門は C2（DB に書く）・C6（知らせは前から：完了にした人でない担当者・作った人へ。`NotifyGateway` は変えない）。**口は新しく作らない**（`apis: []`）。`completeTicket` の入力・答え・断りを直す
- **DB の関数の引数は変えない**：`app.ticket_complete(p_ticket uuid, p_todo_checked integer[], p_todo_version integer, p_confirmed boolean)` のまま（前からの試験が引数の形で直に呼ぶ・K63-API-052・063・081）。`p_todo_checked`・`p_todo_version` は**使わない**（null を渡しても通る）。引数を消すのは K-578（その試験も一緒に替える）
- **見る順**（前の順から 3 つを外す）：完了済み（`done`）→ 段・走っている実行・決まっていない承認待ち（`stage`）→ 作業中か（`not_doing`）→ 完了の条件の確かめ印（`not_confirmed`）→ 終わっていない子（`children_left`）→ 書く。外す物：実施事項の版の見張り（`todo_changed`）・範囲の外の番号（`todo_out_of_range`）・残っている項目（`todo_left`）。**未チェックのために断る道は無い**
- **書く物**（1 回の書き込み）：段（完了）・完了の時刻と押した人・やり取りの 1 行（「〇〇が完了にしました」・前のまま 1 つ）・証跡 1 つ。**実施事項の区画・本文の行・確認項目は書かない**（版の行も足さない）。やり取りの更新の行（kind `change`）は足さない（未チェックが残ったことを文に残すかは代表に聞くこと・勧めは残さない）
- 数えるのは書く前の同じ取引の中（チケットの行を `for update` で取った後）。完了の確定と、確認項目のチェックの付け外し（K-435・チケットの行を `for share`）は順に並ぶので、完了が確定した後に付け外しは 409 になり、完了の答えの数はその時点の数と合う
- **答えの形**（201 `TicketCompletion`）：`{ ticket, knowledge_candidates, skipped_reason, unchecked }`。`knowledge_candidates`・`skipped_reason` は前からの契約の欄で、この葉は中身を作らず前のまま（`knowledge_candidates` は常に空・`skipped_reason` は前の文）：チケットからナレッジの候補は作らない決め（代表 2026-11-22 19:26・控え帳）に当たらない訳。欄を契約から外すかは段 6 の完了の帯の葉と PM が決める（この葉は契約の欄を変えない）。`unchecked` は鍵ちょうど `body`・`specs`（どちらも 0 以上の整数・文は返さない）。画面は完了の**後**にこの数を確かめに使う（前の確かめの小窓は `body.doc`・`listTestSpecs` で出す）
- **数える関数** `app.ticket_body_unchecked(p_doc jsonb) returns integer`（中だけで使う・誰にも execute を渡さない）：根から `content` の並びだけを辿り（再帰）、`type = 'taskItem'` で `attrs.checked` が真偽の `true` でない節の数。null・オブジェクトでない・`content` が並びでない節は 0 と数える。画面の数え方（K-572 が書く `uncheckedTasks(doc)`・文は箱の中の段落の字をつないだ物）は同じ定義にそろえる。**そろっていることは K-572 が、画面の数と完了の答えの `unchecked.body` を同じ本文で突き合わせて確かめる**
- **完了したチケットの本文・確認項目は変えられない**（D-150.30・D-150.56）：書き込みの口（K-432 の本文・K-434／K-435 の確認項目）が完了後を 409 にする（この葉は何も足さない）。**完了を取り消す道**：この本線には無い。段 7 の K-388（完了 → 作業中に開き直す）が入ると、`completed_at`・`completed_by` が消えて作業中に戻るので、本文・確認項目はまた直せる。開き直しは本文も確認項目も戻さない（K-388 の「実施事項は完了のときに全部 [x] にした版」の説明は、この葉の後は「完了で書き換えない」になる）
- **契約**（`05_flow/screen_api.py`・前から INPUTS の行が在る口なので本体・overlap_ok）：INPUTS の `completeTicket` は 3 つの欄のまま・REQUIRED_INPUTS は `conditions_confirmed` だけ・VALUE_RANGES の `todo_checked`（`items: integer・minimum 0`）・`todo_version`（`minimum 0`）は残す（送られたときの形の確かめ）・RESPONSES の `completeTicket` に `"unchecked": "object"`・ERRORS_4XX の `completeTicket` から E-CONF-017（409 の項目の説明）・E-VAL-022（422 の項目）を外し説明を直す
- **断る番号**（控え帳）：形の誤り（番号が整数の並びでない・版が整数でない・`conditions_confirmed` が無い・false）は今までどおり 422（欄つき・E-VAL-023 は `conditions_confirmed`）。404・409 は前のまま（体に field・details を付けない）。この葉は新しい番号を足さない
- **E-CONF-017・E-VAL-022 は正本（errors.d・`packages/errors` の目録）から消さない**：口は出さなくなるが、前の完了の小窓（`apps/web/features/F5/approve-complete/complete-dialog.tsx`）が目録の文を引くので、画面の葉 K-572 が小窓を作り直した後に、K-578 が外す（まとめ役に頼むこと：「口が出さない番号が目録に在る」検査が出るなら、K-578 までの例外にする）
- 別の会社・書けない人：前のとおり（404・403）。数える確認項目は自分のチケットの行だけ
