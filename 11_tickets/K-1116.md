## 申し送り

- 開始の日 start_on は K-437 の後も形（`^(?:[0-9]{4}-[0-9]{2}-[0-9]{2})?$`）だけで、口は暦に無い日（"0000-00-00"）を 422「開始は日付で入れてください」で断る。fuzz が当てれば同じ ST202 になる。K-437 の createTicket の値域で直すのがよい（空を許すので `anyOf: [{maxLength: 0}, {format: date}]` の形）
- 登録・再設定の口（createSignup・requestPasswordReset）の契約のメールの形 `^\s*[^@\s]+@[^@\s]+\.[^@\s]+\s*$` も口の受け方（normalizeEmail → EMAIL_RE）の部分集合でない（精査 R の指摘・同じ ST202 の類・今回の回では当たらなかった）。見本："a﹫b@example.com"・"a＠b@example.com"（NFKC で @ になり @ が 2 つ・Python では \s でも @ でもない）・"\ufeff@example.com"（JS の \s は BOM を除いてローカル部が空・Python の \s は BOM を含まない）。前からある別の場所の問題（c）として切る
- 契約の `\S` の値域（空・空白だけを断る欄）は、Python（schemathesis）と JS（口の trim・\s）で空白の字の集まりが違う。updateMemory の body なら "\x1c" は Python で形の外なのに口は 200（ST201 の種）、"\ufeff" は Python で形どおりなのに口は 422（ST202 の種）。同じ形の欄は次のとおり。前からある別の場所の問題（c）として、`[^ \t\n\r\f\v]` などの両方で同じ字の集まりに直す葉を切る

```search
git grep -n '"pattern": "\\\\S"' -- 05_flow/screen_api.py '05_flow/screen_api.d/*.py'
19
```

- 登録の口（createSignup）は EMAIL_RE だけで受け、確かめの口（verifySignup）で部品の signUpEmail が z.email() で断る。部品が断るメール（日本語の名前など）で登録すると、確かめで落ちる。前からある別の場所の問題（c）
