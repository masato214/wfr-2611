## 目的

段 10 のナレッジ（会社・グループ・個人の物を 1 本の木に貯め、AI が読んで守る）が乗る **DB の置き場** を作る（代表の決め 1〜4・13・切り方 0.1〜0.6）。物は「ナレッジのページ 1 つ」で、棚は **会社・グループ・自分** の 3 つ。今ある表 `knowledge_pages`・`knowledge_page_versions`（0073）を使って直し、**フォルダの表 `knowledge_folders` を新しく作る**。

- ページに足す列：1 行の説明 `summary`・必ず守る `is_must`・写しの元 `copied_from_page_id`・フォルダ `folder_id`・並び `position`
- 本文は段 5 と同じ `{doc, text}`（`app.ticket_body_valid`＝K-561 が最後の砦）。前の形の本文は `app.kn_body_from_text` で段落にして移す
- 棚ごとの「読める人・書ける人」を DB の関数と行の守りで決める：会社の棚＝管理者が書く・全員が読む／グループの棚＝そのグループのマネージャーが書く・そのグループの人が読む／自分の棚＝本人だけ。**権限の束（`permissions`・`has_permission`）はナレッジでは使わない**（作り直す）
- 後ろの葉が同じ名前で使う関数（`app.kn_*`・`app.kpage_visible`・`app.kpage_writable`・`app.kfolder_*`）と、共有（K-689）を見える側に足すための器（`app.kn_shared_visible`・`app.kn_shared_folder_visible`＝この葉では常に false）を置く

口は K-675 以降。頼み（上げる・共有）の表は K-687・K-689、上限の設定の行は K-685、破られた数は K-700（この葉は**名前と列の案だけ**を `07_functional/段10-F9/土台-knowledge.md` に書いた）。

## 前提と制約

分類: PERM, CRUD

- **関門は C2（DB）**。口を作らない（`apis: []`・`canvas: []`）。名前の決めは `07_functional/段10-F9/土台-knowledge.md`（1 章）が正本で、**この葉の md は同じ内容を作る手順に落としたもの**。食い違えば土台が勝つ
- **棚の持ち方**：会社＝`scopes.parent_id is null` のグループ・`is_personal = false`／グループ＝その `scopes.id`・`is_personal = false`／自分＝持ち主の主の所属（`members.scope_id`）・`is_personal = true`。会社のいちばん上のグループは 1 社に 1 つ（`app.kn_company_scope()` は消していない最初の 1 つを返す）
- **書ける人・読める人は DB の関数が毎回その時の所属から決める**（行に写さない）。マネージャー＝`scope_memberships.role = 'manager'` で、`tenant_memberships.status = 'active'`。グループの人＝`scope_memberships` の行か `members.scope_id`。役を外す・グループから抜けるとすぐ効く（K674-DB-021・027）
- **管理者でも、入っていないグループの棚は読めない**（代表の決め 3・brief 1：読むのは「その部署の人と共有先」）。承認の画面は DB の関数が中身を渡す（K-688）。この葉の守りはそのままにする
- **新しいページは下書き（`state = 'draft'`）でしか作れない**（行の守りの insert）。公開は「下書きの行を公開に更新する」＝K-680 の関数が行う。下書きのページは持ち主だけが読む・書く。公開済みのページの下書きの版（`kind = 'draft'`）は書いた人だけが読む・書く
- **使わない列は消さず残す**：`parent_page_id`・`form`・`verify_interval_days`・`verified_at`・`verify_due_on`・`topics`・`archived_at`・`archived_to_page_id`・版の `proposed_*`・`decision`・`decline_reason`・`decided_*`・`state = 'archived'`・`kind = 'proposal'`。消す・凍結の印は K-711（表 `knowledge_links` を含む）
- **版の一意**：`unique (page_id, kind, version)` を外し、公開の版は `(page_id, version)`（`kind = 'published'`）、下書きの版は `(page_id)`（`kind = 'draft'` かつ `deleted_at is null`）の部分一意にする。下書きを捨てる＝`deleted_at` を入れる（版の行は消さない・`kaname_app` に delete を渡さない前のまま）
- **必ず守るは公開済みのページだけ**（check `is_must = false or state = 'published'`）。上限の数と本文 2,000 字の判定は K-685・K-680（この葉は列と `app.kn_must_text_max() = 2000` だけ）
- フォルダ：名前 1〜100 字・同じ棚の同じ親の中で名前は重ならない（大文字小文字を分けず・消した物は数えず・自分の棚は持ち主ごと）・深さ 6 まで・親は同じ棚の同じ会社。失敗は引き金が先頭の印（`KNW_FOLDER_SHELF`・`KNW_FOLDER_DEPTH`・`KNW_FOLDER_CYCLE`・`KNW_PERSONAL_SCOPE`）で言い、会社の食い違いは言葉に「同じ会社」を含めて errcode 22023（土台 1.5）
- 並び `position` は整数・既定 0。並べ直しは K-678（フォルダ）・K-681（ページ）の口が決める。この葉は列だけ
- 本文の移し：前の形の行（`{}`・`{text}` だけ）は、守りを足す前に `app.kn_body_from_text(body->>'text')` で置き換える（`where not app.ticket_body_valid(body)`）。同じ migration を 2 度当てても壊れない形にする（`if not exists`・`create or replace`・`drop … if exists`・移しは「合わない行だけ」）
- 行の守りは `05_flow/rls_policies.py` の POLICIES から `python3 scripts/ci/gen_rls.py --tables knowledge_pages,knowledge_page_versions,knowledge_folders -o packages/db/policies/20261125011400_knowledge_shelves.sql`（migration と同じ名前）で作る（policies は生成物・手で直さない）。`python3 05_flow/build_functional.py` で entities.json を作り直す
- 外へ出ない：お知らせも AI も呼ばない。ログにページの題名・本文を出さない
