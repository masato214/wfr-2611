## 目的

運営が朝ワークスペースの一覧を開いたとき、全社の様子が数と種類だけで分かり、気にかける会社が上に来るようにする（行為 A60・用事 J15）。外枠の左のメニューの数の印（K-946）と一覧の上の数（K-965）は、1 本の口 getOpsShell に寄せる（D-156.4）。

- **getOpsShell**（ops:any）：運営の人・受信箱の 4 つの数・期限を過ぎた請求（お金を持つ人だけ）・ワークスペースの数（使っている・止めている・やめる手続き中・気にかける・プランごと）・今月の実行（先月との比）・照合が使えなかった登録の数（D-156.35）
- **listOpsWorkspaces**（ops:any）：1 行は数と種類だけ（中身を返さない・D-156.3）。気にかける 3 つ（代表の答え 2026-11-23（D-156.24・上限に近い会社は出さない＝D-156.72））・絞り込み（view・plan）・探す（q）・並び（sort）
- 止める印の列（D-156.23）を tenants に足す（**書くのは K-970**・この葉は読むだけ）。状態 active・stopped・closing はこの列とやめる手続きの列から決める

- **数える会社**：tenants のうち `deleted_at is null`・`half_made_at is null`・`id <> app.ops_tenant_id()`
- **状態**：止めている（`stopped_at is not null or stop_on <= 日本の今日`・止める日が来たら何もしなくても止まる・D-156.49）→ stopped（state_since＝stopped_at、無ければ stop_on の 0 時（日本））・`deletion_requested_at is not null` → closing（＝deletion_requested_at）・ほか active（＝created_at）。stopped が先
- **プラン**：`app.tenant_plan_id(<会社>)`（K-954 が作り K-961 が「効いている行」に直した 1 か所。来月 1 日から下げる予定の行は今のプランに数えない＝顧客の側と同じ）→ plans（運営の会社の行）の name・key・`limits->>'members'`。null なら plan_name null・limit null。この葉で契約の行を別の式で引かない（同じ決めを 2 つ持たない）
- **人数**：`app.tenant_seat_count(<会社>)`（K-961 の 1 か所・社内の人だけ・ゲスト〔役割 requester〕・AI 社員・自分の AI は数えない・D-156.51。顧客の「いま N 人 / M 人まで」と同じ数）。**PC がつながる人**：社内の人（人数に数える人）のうち、sessions の `kind_id = 'bridge'`・`revoked_at is null`・`alive_at is not null`・`last_seen_at > now() - interval '90 seconds'`（画面の生きている知らせの窓と同じ）を 1 つ以上持つ人の数（`{ connected, total }`・total は人数＝`app.tenant_seat_count`。ゲストは PC をつなぐ人に数えない）
- **今月の実行**：action_runs の `phase is not null and status_id is not null`・`deleted_at is null`・作った時刻が今月（日本時間の月）。prev_ratio は 今月 ÷ 先月（先月が 0 なら null・小数 2 桁）
- **気にかける 3 つ（D-156.24 を D-156.72 で改めた）**・並びは overdue → stuck → pc。**上限に近い会社（前の limit・上限の 90%）は出さない**（代表の答え 2026-11-23・answer=1e8672e4346c）。kind の値は overdue・stuck・pc の 3 つ（K-1006 の断片の enum も 3 つ）：
  - overdue：invoices の `issued_at is not null`・`deleted_at is null`（出していない下書きと消した請求書は数えない）・`status_id <> 'paid'` で `due_on < 今日（日本時間）` があれば。label_value は いちばん古い期限からの日数。`status_id` は K-982 が入金のたびに書く写し（状態の決めの 1 か所は K-982 の `app.invoice_state`・D-156.46。答えは同じ）
  - stuck：action_runs の `status_id = 'stopped'` が直近 7 日に 3 件以上。label_value は件数
  - pc：作ってから 7 日を超え（`created_at < now() - interval '7 days'`）、`alive_at is not null` の bridge のセッションが 1 つも無い。label_value は 作ってからの日数
- **請求の状態**（billing_state）：出した・消していない請求書（`issued_at is not null and deleted_at is null`）のうちいちばん新しい 1 枚（issued_at）が paid（`status_id` の写し）→ paid・期限（日本時間の今日より前）を過ぎた → overdue・ほか unpaid・無ければ null
- **受信箱の数**：inquiries の `deleted_at is null`。unassigned＝担当なし・`state <> 'done'`／mine＝担当が自分（`assignee_ops_member_id = app.user_id()`）・`state <> 'done'`／waiting＝`state = 'waiting'`／later＝`state = 'later'`（数える会社のだけ）
- **期限を過ぎた請求**：`app.ops_require` の行の caps に money が無ければ null。あれば overdue の請求書の件数と金額の合計（税込の円の整数）
- **照合が使えなかった登録**（pwned.unchecked）：security_events の `pwned_check_unavailable` が、その会社の最後の `pwned_check_acknowledged` より後にある会社の数（0086 と同じ見方）
- 答えに会社の中身（チケット・会話・問い合わせの題・メール）を入れない。探す q は管理者のメール（kaname_auth の user）を関数の中で比べるだけで返さない
- 断る番号（控え帳）：ログインなし 401・運営でない・運営の人の行が無い 403（入口）・形の誤り 422（契約）・DB の失敗 503 E-PAGE-003（K-947 の opsErrorReply）・上限 429
