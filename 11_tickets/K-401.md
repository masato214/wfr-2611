## 目的

段 9（F8 渡す・配る）の口の葉（K-402〜K-410）が乗る **置き場** を 1 回だけ作る（切り方.md 1 章「先頭の葉が置き場を 1 回だけ作り、後ろの葉は自分のファイルだけを触る」）。
あわせて、利用者の 1 操作として **渡す前の下見**（詳細の右の「担当者 ▾」を押して相手を選ぶ小窓が開くとき・D-148.2）の口 `previewTicketHandover` を作る。

置き場に入る物：

- 口の登録 `apps/api/src/hooks/handovers.ts`（K-326 の register）：createTicketHandover・answerTicketHandover・listHandoverRules・previewTicketHandover の 4 本。**足す口（listTicketHandovers・withdraw・remind・claim）は、その葉が自分の hooks のファイルを作る**（K-405・K-406・K-410。このファイルに足さない）
- 渡す口・答える口の **振り分け**：入力の確かめ → 共通の確かめ（見えるか・その人ができる種類か・止まり・相手・一緒に切り替えるもの）→ 種類ごとのファイルへ。種類ごとのファイルは、この葉では全部「まだ使えません」（422・E-HND-001）の空の形で、各葉が自分の 1 ファイルだけを本物にする
- 入力の作り直し：今の契約の入力は表の写し（TicketHandoversInput：ticket_id・from_member_id・state・decided_at まで送れる）。渡すは `kind・to_member_id・to_scope_id・reason・ask・reply_due・switch・notify_managers・replaces`（replaces は「別の人にする」：待っている自分の渡しの id。在ればその渡しを取り消してから新しく渡すのを 1 取引で・中身は K-402・K-413）、答えるは `decision・decline_reason・switch` だけにする
- 共通の判定の DB の関数（答える人・その人ができる種類・止まり・返事の期限の既定・一緒に移す物・決まりで整えた切り替え）と、読める人の関数 `app.ticket_involved` の作り直し（グループ宛て・申し出でも、答える人が答えるまでチケットを読める・D-128.115）
- 知らせとメールの送り方（関門 C6）：DB の関数が返したメールの宛てを送り、送れた／送れなかった印を知らせの行に書く部品と、渡しのメールの文（D-148.19：理由とお願いは書かない）
- 答える口の行の決まり：今は「相手（to_member_id）だけ」（scripts/ci/row_rules.mjs の recipient）。申し出（答えるのは担当者）・グループ宛て（答えるのはそのグループを管理する人）でも入口を通るように、`OP_RULES.answerTicketHandover` を `app.handover_answerer(id, app.user_id())` にする

上へ上げる（kind escalate）は段 9 では作らない（D-148.1）。振り分けで 422・E-HND-001 を返し続ける。

### 振り分け（create/index.ts・answer/index.ts）

渡す（`createTicketHandover`・POST /tickets/:id/handovers・入口の行の言葉は write＝`app.ticket_writable(id)`）：

1. 入力（`input.ts` の `parseCreate`）：kind が無い・3 つの値（pass・offer・distribute）でない → 422（VALIDATION_ERROR・欄 kind）。kind が escalate → 422・E-HND-001（契約の kind は 3 つだけ・契約の外の値・DB を引かない）。to_member_id と to_scope_id を両方 → 422 欄 to_member_id。offer に to_member_id・to_scope_id・reply_due → 422 その欄。理由は NUL を含んだら 422（欄 reason・VALIDATION_ERROR・黙って取り除かない・answer=c8b3f4c3aef8）、NUL 以外の制御文字を落として、前後の空白（全角も）を落として空なら 422・E-HND-007 欄 reason。reply_due は時差つきの ISO 8601 でなければ 422（VALIDATION_ERROR 欄 reply_due）、今より後でなければ 422・E-HND-008 欄 reply_due。switch は object で、鍵が children・links・group（真偽）・axes（uuid の並び）だけでなければ 422・VALIDATION_ERROR 欄 switch（形の誤り・番号なし）。replaces は uuid の形でなければ 422（VALIDATION_ERROR 欄 replaces）、kind が pass でなければ 422 欄 replaces（別の人にするのは引き継いでもらうだけ）
2. （DB の 1 取引・読むだけ）`select app.handover_gate($1, $2) as v`

### 知らせとメールの送り方（notify.ts・mail.ts）

- 種類の葉の DB の関数は、知らせの行（notifications・channel 'inapp'・event_kind_id は 'handover.' で始まる名前・dedupe_key つき）を入れ、メールを出す宛てを `mails: [{ notification_id, handover_id, email, event, ticket_id, ticket_number, ticket_title, actor_name, to_name, reply_due }]` で返す（`MailRow` の型。handover_id はログの where を組むのに使う）
- `notify.ts` の `sendHandoverMails(d: HandoverDeps, ctx: { tenantId: string; userId: string }, mails: MailRow[], where: string): Promise<{ sent: string[]; failed: string[] }>`：ctx は口が withTenant に渡したのと同じ会社と人（a の文脈）。1 通ずつ `mail.ts` の `handoverMail(row, webBaseUrl)` で文を組んで `d.mailer` で送る（mailer が無ければ送れない扱い）。送れなかったらログに `[handover] <where>：メールを送れなかった → <mailTag(email)>: <例外の種類>`（メールと文は出さない）。送り終えたら `withTenant(d.appPool, ctx, (c) => c.query("select app.handover_mail_mark($1, $2)", [sent, failed]))`（app.handover_mail_mark は app.tenant_id() の会社の行だけに印を付けるので、会社の文脈が要る。落ちたら 1 回だけやり直し、それでも落ちたらログに `[handover] <where>：印を書けなかった → <例外の種類>` の 1 行・答えは変えない）。投げない。**where は「<種類>:<渡しの id>」**で、葉ごとに次の字にそろえる：K-402 `pass`・K-403 `answer-pass`・K-406 `withdraw`／`remind`・K-407 `overdue`・K-408 `offer`／`answer-offer`・K-409 `distribute`／`answer-distribute`・K-410 `distribute-group`／`claim`（例 `pass:0193…`。ログで渡しを追えるように渡しの id を入れる・人の名前とメールは入れない。K402-API-012 などがログの渡しの id を見る）
- `mail.ts` の event と件名（本文は相手の名前・番号と題名・返事の期限（あれば・日本時間「11月23日（月）18:00」）・`<webBaseUrl>/tickets/<ticket_id>` だけ）：

  - `offered`（申し出が来た）「【Kaname】{actor}さんが引き継ぎを申し出ています（{番号}）」
  - `reminded`（催促）「【Kaname】{actor}さんから引き継ぎの返事の催促が届きました（{番号}）」
  - `declined`（断られた）「【Kaname】{actor}さんが引き継ぎを断りました（{番号}）」
  - `overdue`（期限切れ）「【Kaname】{to}さんの引き継ぎの返事がまだありません（{番号}）」
  - `distributed`（配られた）「【Kaname】{actor}さんからチケットが配られました（{番号}）」
