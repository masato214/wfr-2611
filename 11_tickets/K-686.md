## 目的

ページを書き終える前・上の棚に上げるのを頼む前に、**似たページが既にないか**を探す口 1 本を作る（契約は K-675 が宣言済み・今は 501）：`findSimilarKnowledge`（POST /api/v1/knowledge/similar・入力 `{ title, desc?, text?, exclude_page_id? }`・200 `{ pages: PageBrief[] }`）。入力・答え・断りは土台 2・3.2・4 章。

- 探し方は pg_trgm の似ている度合い。**題名＋1 行の説明**を、ページの題名＋1 行の説明と比べる。本文（`text`）が付いていれば、**本文の頭**を、ページの公開済みの最新の本文の頭と比べる。大きい方の点で並べる
- **自分が見える棚の公開済みのページだけ**（会社・入っているグループ・共有された物・自分の棚）。自分自身（`exclude_page_id`）・まだ書き終えていないページ・書いている下書きの版・消したページ・見えないページは出さない。点が **0.3 以上**の上位 **3 件**。無ければ空
- 口は DB に書かない。重さ（1 万ページで何 ms か）を作る段で測る行（K686-API-014）を持つ
- 呼ぶ画面は 2 つ：書き終える前（K-691）は書いているページ自身を `exclude_page_id` で外して呼び、上げる前（K-692）は上げるページ自身を外して呼ぶ。**入力に「上げる先の棚」は持たない**（土台の形のまま）。見える棚の全部から探した上位 3 件を返す（下の「上げる前の探し方」）

- **口は 1 つの取引（`withTenant`）の中で関数を 1 回呼ぶ**：①`head` ＝ 題名 ＋ 空白 ＋ 説明（無ければ空）②`body` ＝ `text` の頭 500 字（コードポイントで切る・無ければ空）③`select * from app.kn_similar($1, $2, $3)`（`exclude_page_id` が見えない・無い id でも**そのまま渡して構わない**＝一致するページが無いだけ・在るかを漏らさない）④各行を `{ id, title, desc: summary, place: placeText(shelf_name, folders) }`（`shape.ts`・`›` でつなぐ）にする → 200 `{ data: { pages } }`
- **入力は入口が整える**：題名・説明・本文は入口が前後の空白を落とし NFKC にする（`apps/api/src/contract/op.ts`・全角の英数と空白は半角になる）。題名は空白だけで 422・200 字まで・説明は 200 字まで・`text` は 10,000 字まで・知らない欄は 422（契約）。**大文字小文字は関数が `lower` でそろえる**
- **点の下限と件数は定数**：口の定数 `SIMILAR_MIN = 0.3`・`SIMILAR_LIMIT = 3`（関数の 4 つ目の引数の既定と同じ 0.3 を口が明示して渡す）。変えるときは K-686 の md と試験を同じ変更で直す
- **日本語の扱い（照合順序）**：pg_trgm は文字の分類（照合順序）で「文字」と数える物が決まる。日本語の題名が数えられない DB（照合順序が `C`）では点がいつも 0 になる。**試験の DB（K686-DB-001）と staging・本番の DB で「日本語の似ている度合いが 0 より大きい」ことを確かめる**（申し送り・環境の準備）。数えられない DB でも口は 200（空）を返し、落ちない
- **DB の失敗の言葉 → 番号**：関数が落ちた（拡張が無い・DB が落ちた）→ 503 E-PAGE-003（何も書かない・ログに例外の種類だけ・題名と本文を出さない）
- 外へ出ない：DB に書かない・証跡を残さない（読みは数えない）・メールもお知らせも AI も呼ばない。ログに題名・本文を出さない
- **権限の波及**：毎回、今の所属と行の守りで見える物を決める（入り直しは要らない）

### 画面が使う答えの形（K-691 の「似たページ」小窓・K-692 の「上げる」小窓が使う）

- 探す → `{ data: { pages: [{ id, title, desc, place }] } }`（200・最大 3 件・似ている順）。`place` は「会社 › 経理 › 請求」のように `›` でつないだ字（自分の棚は「自分」）。画面は 1 件ずつ「開く」（そのページの読む画面）と「それでも書き終える／上げる」を出す。**空なら小窓を出さずにそのまま進む**

- 422 は題名が空・長すぎる（契約が断る）。画面も同じ数（題名 200 字・説明 200 字）で数える

## リスクと懸念

- **重さ**：公開済みの全ページを毎回走査し、1 万ページで 1 回の呼びが目標 0.5 秒（試験は時間を記録するだけ）。1 分 30 回の上限でしのぐ。遅ければ、点の計算に使う文字列（題名＋説明＋本文の頭）を保存する列と trgm の索引を足す（別の葉）。作る段が測った時間を申し送りに書く
- **日本語と照合順序**：pg_trgm は照合順序が `C` の DB で日本語を数えない。staging・本番の DB の照合順序を環境の準備で確かめる（K686-DB-001 は試験の DB だけを見る）。数えられない DB では口が常に空を返し、似たページの小窓が出ない（落ちはしない）
- **行の守りの計算が走査の中に入る**：見えるかどうかを行の守りに任せるので、1 万行それぞれで見える関数（`kn_shelf_readable` など）が走る。K-674 が見える関数を重くすると、この口も遅くなる。K686-API-014 が見る
- **0.3 の下限は仮**：日本語の短い題名では、似ていなくても 0.3 を超えることがある・似ていても超えないことがある。作る段で実データの近い題名を数件当て、下限を決め直す（定数 `SIMILAR_MIN` と試験を同じ変更で直す）
