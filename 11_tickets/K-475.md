## 目的

チケットの一覧で絞った条件（見え方・絞り込み・列・並び・まとめ方）に名前を付けて残し、あとで開き直せるようにする口を作る。契約の口 `listSavedViews`（GET /api/v1/saved_views）と `createSavedView`（POST /api/v1/saved_views）は今 501。
画面（保存の小窓・左のメニュー・一覧の「保存した条件」）は K-479、直す・消すは K-476。

- 見える人は 2 通り（D-128.83・D-128.119）：自分だけ（share `self`）／グループの全員（share `group`）。グループの全員に見せるときは、見せるグループ（`scope_id`）が要り、そのグループが見える人だけが保存できる。契約の入力 `SavedViewsInput` には `scope_id` が無かったので、入力を作り直す（`member_id` は受けない・呼んだ人に決める）
- 並び・まとめ方・条件は `filters`・`columns` の jsonb に入れる（列は足さない・範囲 Q8）。口は形と大きさだけを確かめ、中の意味は見ない（意味を持つのは一覧の口 K-472〜K-474 と画面）
- 「左のメニューに出す」「増えたら知らせる」は作らない（列が無い・時間で動く仕組みが無い・D-151.9）。画面は押せない形で置く
- 同じ名前は 1 人 1 つ（大文字小文字・全角半角の違いも同じ）・1 人 50 件まで（仮）。画面の絵 f7-save-error（名前が空・同じ名前・上限・口が断った）の 4 つに、口の側の番号と文を決める

## 前提と制約

分類: LIST, CRUD, PERM

- **素の読み書き（generic-ok.json）では足りない。hooks で作る**（切る段で `apps/api/src/contract/op.ts` を読んで確かめた）。足りない訳が 5 つ：① 一覧の共通の処理は `share` を読まない（`scope_id` と `sort` だけ。契約には `share` の問い合わせがある）② 並びは主キー（uuid）で、名前の順にならない ③ 入力に `scope_id` が無く、共通の作成は `scope_id` が無ければ「呼んだ人の席のグループ」を入れる（`withScope`）ので、見ているグループに見せられない ④ 名前の空・長さ・重なり・数の上限・条件の形の確かめが無い ⑤ 答えが表の行そのもの（tenant_id・created_by・deleted_at を含む）。行の守り（`policies/0072_ticket_around.sql`）は 2 層目として生かす（自分と見えるグループだけ読める・他人の名前で入れられない・見えないグループに見せられない）
- 見える範囲の決め方（口の文と行の守りで同じ条件・2 重）：作った人本人の物、または share が group で `scope_id` が `visible_scopes(自分)` に入る物。消した物（`deleted_at`）は口の文で外す（行の守りの select は消した物を外さない・外すと消す更新が返す行を読めなくなる）
- **入力の決まりは全部、契約に書く**（控え帳 11-20 16:51：422 は契約に書ける形の誤りだけ。契約の外の例外の行は使わない）。名前の長さと字・share・density・filters・columns・share と scope_id の組み合わせは、下の「契約に書く値域」の pattern・minLength・maxLength・enum・maxItems・INPUT_RULES で書く。口（hooks の input）は同じ決まりを正本のエラーの番号つきで返す。契約の長さと pattern は、入口の normalize（NFKC と前後の空白）の後の字に掛かる決まり
- 名前：入口の normalize（NFKC と前後の空白）の後、1〜60 文字（文字の数で数える）。空・空白だけ（全角も）は 422 E-VWS-001、61 文字以上は 422 E-VWS-002、途中の制御文字（改行・タブ・BEL ほか。C0・DEL・C1）は 422 E-VWS-008。NUL（U+0000）は入口（K-427）が全部の口で 422 にするので、この葉の試験は NUL を送らない（控え帳 17:46）
- share は `self`（既定）か `group`。それ以外は 422（契約の VALUE_RANGES の enum・欄 share）。`group` で `scope_id` が無い・null は 422 E-VWS-003。`scope_id` はそのグループが同じ会社・消していない・`visible_scopes(自分)` に入るときだけ。無い・別の会社・消した・見えない は 404 E-VWS-004（欄なし・field も details も付けない・存在を教えない。自分だけの保存に付けた `scope_id` も同じ。`scope_id` は「どのグループの一覧で作ったか」を残す印にもなる）
- density は `normal`（既定）か `compact`。それ以外は 422（欄 density）
- filters は入れ物（object。配列・文字・null は不可）で、**欄は 8 個まで・欄の名前は英数字と `_` の 1〜40 字・値は 500 字までの文字か数か真偽か、同じ決まりの値だけを持つ入れ物 1 段（32 欄まで）**（配列・null は値に使えない）。columns は文字の並び（50 個まで・1 つ 40 文字まで）。外れたら 422 E-VWS-007（欄は filters か columns）。既定は filters `{}`・columns `[]`。2026-11-21：JSON にして 16 KB という総量の決まりは、契約の言葉（pattern・長さ・個数・欄の有無）では書けないので、上の構造の上限に置き換えた（K-479 が送る `{v, view, q, params}` は収まる。最大でも 約 140 KB で、入口の共通の 1MB の守りの内）
- 同じ名前：同じ人の消していない物の中に、`lower(name)` が同じ物があれば 409 E-VWS-005（欄 name）。人が違えば同じ名前で作れる。消した物は名前をふさがない
- 数の上限：同じ人が作った消していない物が 50 件あれば、51 件目は 409 E-VWS-006。ほかの人の物・消した物は数えない（数字は仮・代表に聞かず PM の決めとして報告する）
- 同時に 2 回押しても数と名前の確かめがすり抜けない：保存は 1 つの取引の中で、その人ごとの助言ロック（`pg_advisory_xact_lock`）を取ってから数と名前を数える。ロックの外の最後の砦は、一意の索引（同じ名前・直に入れた場合）
- 証跡（関門 C2）：`app.record_audit('saved_views.create', 'saved_views', <id>, 'C2', {share})`。名前・条件・グループは証跡に入れない（条件に打った言葉が証跡に残らないように）。同じ取引で書く
- 知らせは出さない（受け箱に書かない・メールも出さない）。グループの全員に見せても、見える人に知らせは行かない（「増えたら知らせる」と同じく D-151.9 の外）
- ログに名前と条件を出さない。ログに出すのは「一覧を 500 行で切った」の 1 行だけ
- 保存する口で DB が落ちたら（見えるグループの確かめの所でも、書く所でも。1 つの取引なので何も残らない・K475-API-028・029）、503 E-PAGE-003（止める側に倒す・控え帳 2026-11-22 18:30 の決め。ログは場所と例外の種類だけ）。一覧を読む所で DB が落ちても 503 E-PAGE-003（K475-API-030・ログに名前の字を出さない）
- 一覧は上限 500 行で切る（K-351 と同じ形：501 行読み、501 行目があれば捨ててログに 1 行）。cursor・limit は入口の共通の形の確かめだけで、口は全部を返す。見える条件は 1 人あたり多くても 50＋見えるグループの物なので、普通は 500 に届かない

### 契約に書く値域（screen_api.d/K-475.py の VALUE_RANGES・INPUT_RULES・contract_shape.d/K-475.py の VALUE_RANGES）

名前の pattern は「見える字が 1 つ以上・途中に制御文字（C0・DEL・C1）が無い・前後は空白（改行・タブも）でよい」。filters は上の構造の上限。同じ辞書を 2 か所に置くと YAML の別名が出る（build_api の注）ので、繰り返す所は関数で作る。

```python
_VISIBLE = r"[^\s\u0000-\u001f\u007f-\u009f]"; _NO_CTRL = r"[^\u0000-\u001f\u007f-\u009f]"
_NAME = rf"^\s*{_VISIBLE}(?:{_NO_CTRL}{{0,58}}{_VISIBLE})?\s*$"   # 前後の空白を除いた 60 字まで（maxLength は空白込みで数えるので使わず pattern で書く・ST201）
def _key(): return {"pattern": "^[A-Za-z0-9_]{1,40}$"}
def _leaf(): return [{"type": "string", "maxLength": 500}, {"type": "number"}, {"type": "boolean"}]
_FILTERS = {"maxProperties": 8, "propertyNames": _key(),
            "additionalProperties": {"anyOf": _leaf() + [{"type": "object", "maxProperties": 32, "propertyNames": _key(), "additionalProperties": {"anyOf": _leaf()}}]}}
VALUE_RANGES = {"createSavedView": {
    "name": {"minLength": 1, "pattern": _NAME},
    "share": {"enum": ["self", "group"]},
    "density": {"enum": ["normal", "compact"]},
    "filters": _FILTERS,
    "columns": {"maxItems": 50, "items": {"type": "string", "maxLength": 40}},
}}
# group に見せるなら scope_id（null でない）が要る。share が self か無いときは scope_id は何でもよい（null も）
INPUT_RULES = {"createSavedView": {"anyOf": [
    {"not": {"required": ["share"]}},
    {"properties": {"share": {"enum": ["self"]}}},
    {"required": ["scope_id"], "properties": {"scope_id": {"type": "string"}}},
]}}
# 条件（filters）の欄の名前の決まりは OpenAPI 3.0 に書く場所が無い（propertyNames は 3.1 から）ので、口の振る舞いのまま 422・E-VWS-007（ST202）。schemathesis.toml に createSavedView の行を足す
UNEXPRESSIBLE_422 = {"createSavedView": ["条件（filters）の欄の名前の決まり（英数字と _ の 40 字まで）"]}
```

この表現で、名前の空・空白だけ・制御文字・61 文字以上、share・density の言葉の外、group で scope_id が無い・null、filters が入れ物でない・欄が 9 個以上・値が配列か null か長い、columns の個数と長さは、どれも契約の外の入力になる（試験 015・017・019）。K-476 の `updateSavedView` も同じ値域を使う（K-476 は自分の断片に同じ字を写す）。

**契約の長さと入口の normalize の差**：口は入口の normalize の後の字で数える。契約の pattern は送った字に掛かるので、前後に空白の付いた 61 字以上や、NFKC で字数が変わる名前（合字など）の端は、契約の外でも口が受ける。この端の扱いは PM の決めを待つ（「PM に確かめたいこと」）。
