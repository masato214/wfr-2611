## 目的

ナレッジのページを書き始める・書いている途中を自動で保存する・やめる、ための口 3 本を作る（契約は K-675 が宣言済み・今は 501）：`createKnowledgePage`（POST /api/v1/knowledge_pages・201）・`saveKnowledgeDraft`（PATCH /api/v1/knowledge_pages/:id/draft）・`discardKnowledgeDraft`（DELETE /api/v1/knowledge_pages/:id/draft）。入力・答え・断りは土台 2・3.2・4 章。「書き終える」（公開・版が進む）は K-680。

- 作ったページは**下書きのページ**（`state = 'draft'`・持ち主だけが読める・版の数は 0）で、空の下書きの版 1 つが付く。1 度も書き終えていないページを「やめる」と、ページごと消える
- 公開済みのページを直すときは、最初の本文の保存で**下書きの版**（`kind = 'draft'`）ができる。1 ページに生きている下書きの版は 1 つだけ（K-674 の部分一意）。**別の人が下書き中なら 409 E-KNW-012**
- **自動保存の頻度は画面（K-683）の仕事**。口は来た物を保存するだけ（1 分 120 回まで）
- 書く人は棚で決まる（切り方 0.3）：会社の棚＝管理者／グループの棚＝そのグループのマネージャー／自分の棚＝本人。見えない棚・ページは 404・見えるが書けないは 403

- **消した行は入口を通る（K-675 の `scripts/ci/row_rules.mjs` の `RULES.write.knowledge_pages` の直し＝`(deleted_at is not null or app.kpage_writable(id))` に依存）**。入口の行の守りは消したページを隠さず、`kpage_writable` は消したページで false になる。K-675 の直しが無いと消したページへの保存・やめるは入口で 403 になり、口まで来ない。直した後は、消したページは入口を通って口に来て、口の読みが `deleted_at is null` つきで 404 にする（下の保存・やめるの ①）
- **口は 1 つの取引（`withTenant`）の中で確かめてから書く**。**確かめで断る（404・403・409・422）前に何も書かない**（同じ要求の題名だけが先に変わらない）。取引の外で例外を受け、DB の断りを番号に直す
- **見える・書けるは `app.kpage_visible(id)`・`app.kpage_writable(id)`（K-674）**：見えない（無い・消した・別の会社・他人の自分の棚・他人の下書きのページ・入っていないグループ）→ 404（体は `{ error, code }` だけ・在るかを漏らさない）／見えて書けない→ 403
- **作る**（`createKnowledgePage`）：入力 `{ shelf, group_id?, folder_id?, title, desc? }`（題名は入口が前後の空白を落とし NFKC にする・200 字まで・説明は 200 字まで）。①`resolveShelf` が null → 404 ②棚に書けない（`app.kn_shelf_writable`・自分の棚は本人）→ 403 ③`folder_id` が見えない・無い・消した・**同じ棚でない**→ 404（`app.kfolder_visible` と、棚（scope・自分か・持ち主）の等号）④ページを `state = 'draft'`・`owner_member_id` ＝自分・`scope_id`／`is_personal` は棚のとおり・`current_version = 0`・`summary` ＝説明（無ければ空）・`folder_id`・`position` ＝同じ棚・同じフォルダの消していないページの最大 +10（無ければ 10）で入れる ⑤空の下書きの版を 1 つ入れる（`kind = 'draft'`・`version = 1`・`author_member_id` ＝自分・本文 `{ doc: { type: "doc", content: [] }, text: "" }`＝K-674 の `app.kn_body_from_text('')` と同じ形）⑥証跡 → 201 `KnowledgePageStub`（`{ id, title, desc, state: "draft", must: false, place }`・鍵ちょうど 6・`place` は K-675 の `toPlace`）
- **保存する**（`saveKnowledgeDraft`）：入力 `{ title?, desc?, doc? }`（1 つは要る＝契約が 422・`text` を送ると 422）。①ページを `deleted_at is null` つきで読む（消したページ・見えない→404）・書けない→403 ②`doc` があれば K-675 の `parseDocInput(doc)` で確かめ（外れは 422・欄 `doc`・**何も保存しない**）③**下書きの版**：自分の生きている下書きの版があればそれを直す（本文を上書き・`updated_by`）。無ければ入れる。入れ方は `insert into knowledge_page_versions (…kind = 'draft'・version = ページの current_version + 1・author_member_id = 自分…) on conflict (page_id) where kind = 'draft' and deleted_at is null do nothing returning id` と決める（取引の中で一意違反の例外を出さない。PostgreSQL は 1 回の一意違反で取引が中止になり、同じ取引の中で読み直せないため）。**戻りが空なら**、自分の下書きの版を読み直す（行の守りで他人の下書きの版は見えない）：見つかれば本文を直す（同じ人が 2 つの画面から同時に保存して競り負けた場合。409 にしない）・見つからなければ他人の下書きに当たったので 409 E-KNW-012（取引は戻る）④`title`・`desc` があれば**ページの列（`title`・`summary`）に直ちに書く**（下書きの版には持たない＝K-674 の表に列が無い。本文だけが書き終えるまで公開に出ない）⑤題名か説明が**変わったときだけ**証跡 ⑥200 `{ saved_at, title, desc }`（`saved_at` は版（`doc` を送った）かページ（送らなかった）の更新の時刻の ISO 8601〔UTC・`Z`〕・`title`・`desc` は保存後のページの値）
  - まだ書き終えていないページ（`state = 'draft'`）は持ち主だけが書ける（版は `version = 1` の下書きの版をそのまま直す）。**必ず守るのページ（`is_must`）は本文が 2,000 字を超えても下書きは保存できる**（止めるのは書き終える K-680・E-KNW-041）
  - 書けない人が別の人の下書きに割り込んでも、本文は上書きされない（行の守りで見えず、入れるのは部分一意で止まる）
- **やめる**（`discardKnowledgeDraft`）：①ページを `deleted_at is null` つきで読む（消したページ・見えない→404）・書けない→403 ②自分の生きている下書きの版が無い（公開済みで下書き無し・別の人の下書きだけ）→ 409 E-KNW-030 ③下書きの版に `deleted_at` を入れる（版の行は残す）。**まだ 1 度も書き終えていないページ（`state = 'draft'`）は、ページにも `deleted_at` を入れる**（ページごと消える）→ 200 `{ id, page_deleted }`（ページごと消えたら true）④証跡。**公開済みのページは何も消えない**（公開の版・ページはそのまま・捨てた後にもう一度保存すると新しい下書きの版ができる）。ページごと消した後の保存・やめるは 404（二度押し）
- **DB の失敗の言葉 → 番号**：口は取引の外で例外を受ける。他人の下書きは上の `on conflict do nothing` と読み直しで 409 E-KNW-012 にするので、取引の中で例外にしない。取引の外で `23505`（部分一意 `knowledge_page_versions_draft_uq`）を受けたとき（`on conflict` で拾えなかった競りだけ）は 409 E-KNW-012。**それ以外の例外は 503 E-PAGE-003（何も書かない・ログに例外の種類だけ・題名と本文を出さない）**
- **証跡**：同じ取引で `app.record_audit(action, 'knowledge_pages', <ページの id>, 'C2', '{}')`。action は 作る＝`knowledge.page.create`・やめる＝`knowledge.draft.discard`・題名か説明が変わった保存＝`knowledge.page.retitle`。**本文だけの保存（自動保存）は証跡を残さない**（多いので）。題名・本文を証跡に入れない。断った操作・落ちた操作には残さない（取引が戻る）
- **権限の波及**：マネージャーの役を外された・グループを抜けた・付けられた直後も、次の操作から今の所属で決まる（毎回 DB の関数が決める）
- 外へ出ない：メールもお知らせも出さない。AI も呼ばない。ログに題名・本文を出さない
- **入口の `normalize`（NFKC と前後の空白）は本文 `doc` の文字にも掛かる**（`apps/api/src/contract/op.ts`・K-675 の前提と同じ）。段 5 の本文の口 K-432 と同じ扱い（`doc` は入口の整えの後の形を保存する）に合わせる。別の扱いが要るなら、この葉の作る段で K-675 に頼む

### 画面が使う答えの形（K-683 の「ページを書く」画面・K-684 の「＋でページ」が使う）

- 作る → `{ data: { id, title, desc, state: "draft", must: false, place } }`（201）。画面は答えの `id` でページの「書いている」画面を開く（本文は空）
- 保存 → `{ data: { saved_at, title, desc } }`（200）。画面は `saved_at` を「保存しました ○:○○」の字にする。**題名・1 行の説明は保存のたびに公開中のページにも効く**（本文だけが書き終えるまで公開に出ない）。別の人が書いている（409 E-KNW-012）は「ほかの人がこのページを書いています」と出す（文面は台帳・仮）
- やめる → `{ data: { id, page_deleted } }`（200）。`page_deleted` が true なら画面は木に戻る・false なら読む画面に戻る

## リスクと懸念

- **題名・説明が下書きでなく直ちに効く**のは、版の表に題名・説明の列が無いため。公開中のページの題名を直しかけて「やめる」を押しても、題名は戻らない（本文は戻る）。代表が「書き終えるまで題名も公開に出さない」を選んだら、K-674 が版の表に `draft_title`・`draft_summary` を足し、この葉の保存と K-680 の書き終えるを直す（申し送り）
- 部分一意の競りで 409 E-KNW-012 と「自分の版の読み直し」を見分ける所が要。自分の下書きの版は行の守りで見えるので、入れる前の読みで見つかれば更新・無ければ `on conflict do nothing returning id` で入れ、戻りが空なら読み直す（見つかれば更新・無ければ他人の物で 409）の順で書く（K679-API-011・015 が見る）。一意違反の例外を取引の中で受けない
- 本文の `normalize`（NFKC）が `doc` の文字に掛かる（前提と制約）。本文の文字が変わることを段 5 の K-432 と同じに受け入れる前提
- 見込みが 1 時間ぎりぎり（口 3 本・下書きの版の扱い・試験 26 行）。超えるなら「保存」を別の葉に分ける（番号はまとめ役が決める）

## 申し送り

- K-675（土台の葉）：K-679 が使う E-KNW-012・030 は台帳にある。追加の頼みは無い
- K-674（土台の葉）：題名・説明を書き終えるまで公開に出さない案を採るなら、`knowledge_page_versions` に `draft_title`・`draft_summary`（空可）を足す（代表の答え次第・勧めは足さない）
- K-680（書き終える）：下書きの版を公開に更新する（`kind = 'published'`・番号は今の `current_version + 1`・`published_at`・`published_by`）。本文の 2,000 字の確かめと証跡は K-680。題名・説明はこの葉の保存で既にページに入っている
- K-683（ページを書く画面）：保存の間隔は画面が決める（口は 1 分 120 回まで）。保存の答えの `saved_at` を「保存しました」に使う。409 E-KNW-012 は「ほかの人がこのページを書いています」・やめるの答えの `page_deleted` で戻り先を決める。1 行の説明の字数の上限 200・題名の上限 200 は契約が 422 で断るので、画面も同じ数で数える
- K-681（ページを動かす・消す）：下書きのあるページを消す・動かす扱いは K-681 が決める。この葉は何も決めない
- K-681・K-690（置き場の形）：`readPlaceOf` はこの葉の `draft-shape.ts` が持つ。K-681 の `page-edit-shape.ts` は作らず、K-690 は同じ名前で使う
- K-677（ページを読む）：`draft`・`body` はこの葉が作る下書きの版（kind draft・自分の物）を読む（形は土台 3.1）

## 代表に確認中・勧めで切る

- 題名と 1 行の説明を直したとき、書き終えるまで公開中のページに出さないか。実例：営業のマネージャーが公開中の「見積もりの出し方」の題名を「見積書の出し方」に直し、本文を書いている途中でやめた → 勧めは「題名・説明は保存のたびにすぐ公開中のページにも効く（本文だけが書き終えるまで出ない）」。勧めのまま切った。違えば K-674 に版の表の列を足してもらい、K-679 の保存と K-680 の書き終えるを直す（K679-API-008・014 の期待が変わる）
