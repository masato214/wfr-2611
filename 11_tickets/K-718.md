## 目的

K-698 が足す契約の道具 `knowledge_open`（ナレッジのページを開く）を、**自分のAI（本人の Claude Code）に見せる**。Bridge の道具のサーバー（`kaname-tools.ts` の台本・MCP の「kaname」）に定義を足し、仕事の種類ごとの出し分け・進み具合の字・見つからないときの文を決める。契約の口・DB・道具の鍵の扱いは K-62 のまま（K-698）。

- 道具の定義：名前 `knowledge_open`・入力は `page_id`（文字・必須）だけ。説明は AI が読む（「ナレッジの目次に並んだページを、ページの id を渡して開いて読む」）
- 出し分け：**チケットの仕事は `ticket_read` と `knowledge_open`**・**会話の仕事は `ticket_read` 以外の全部（`knowledge_open` を含む）**・ログインの試しは何も出さない。手元の口（`tool-relay.ts`）は渡された道具の名前の一覧で通すので、口は変えない
- 見つからない（契約の口が 404）：AI に「そのページは見つかりません」とだけ返す。在るかどうか・見えない訳を書かない（K-698 の「同じ答え」を守る）。ほかの失敗は前のまま（「Kaname に置けませんでした：…」）
- 進み具合の字：「ナレッジを開いています」（内部の道具の名前を出さない）
- **Bridge の版の約束（`BRIDGE_PROTOCOL`）は上げない**：古い Bridge は道具が見えないだけで、必ず守るは本文ごと届く（K-697 の `canOpen` が道具のある仕事だけ「開ける」と言う）。古い Bridge を断らない
- 許可：`KANAME_TOOL_RULE = "mcp__kaname"` は聞かずに使える道具（読むだけ・外に出ない）で、`knowledge_open` も同じ（前のまま・変えない）

## 前提と制約

分類: AI

- **`apps/bridge/src/kaname-tools.ts`**：`TOOL_DEFS` の `ticket_read` の**すぐ後**に `knowledge_open`（`{ name, description, inputSchema: { type: "object", properties: { page_id: s("ページの id（ナレッジの目次にある id）") }, required: ["page_id"] } }`）。`TICKET_TOOL_NAMES = ["ticket_read", "knowledge_open"]`。`toolDefsFor`：チケット＝`TICKET_TOOL_NAMES` に当たる定義（定義の並びのまま＝`ticket_read`・`knowledge_open`）・ログインの試し＝空・それ以外（会話・種類なし）＝`ticket_read` を除いた全部（`knowledge_open` を含む）。**会話の仕事では `ticket_read` だけを除く**書き方にする（`TICKET_TOOL_NAMES` で除くと `knowledge_open` が消える）

- 手元の口（`tool-relay.ts`）・`loop.ts`・`runner.ts` は変えない（渡す道具の名前は `toolDefsFor(kind)` から来る）。`KANAME_TOOLS` の環境変数（その仕事の道具の名前）も同じ
- ログに道具の入力の中身（ページの id）・答え（本文）・道具の鍵・PC の印を出さない（前のまま）
- 外へ出ない：メールもお知らせも出さない。本人の PC の中のファイルを読まない（`artifact_put` と違い、PC のファイルは使わない）
