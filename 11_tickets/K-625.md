## 前提と制約

分類: TOOL

- 足すのは `spec-dependencies.yaml` の `layer_checks` の行だけ（`file`・`check`・必要なら `elsewhere`・`manual`）。検査の道具・台帳の中身は変えない
- **検査は実際に層を読む物だけ**：check が指す道具の字に、層のファイル名が在ること（`.d` の断片の置き場だけは置き場の名前でよい。`ci`・`web` のような上のフォルダの名前では通さない）。design-gate.json の字も数えるのは、check が design_gate.py を呼ぶ行だけ（試験 004）。名前を読まない検査を結ぶのは「検査があるふり」で、赤にする
- **G27 で重ねて流さない**：別の段（G65 など）が既に流している試験は `elsewhere: G<番号>` を付ける（K-156）。G27 が自分で流す層は軽い検査（数秒）だけ。印が本当に段で流れているかは ci_wiring_gate の W5 が見る。段の番号は `grep -n "<試験の名前>" .github/workflows/v3-gate.yml` で探す
- G27 が自分で流す層（check があり elsewhere が無い）のファイルは、範囲の地図（`scripts/ci/ci_scope.json` の gates の 27）に当たらなければならない（K-245 の 011）。当たらない層（`ticket-flow.yaml`・`ai-team.yaml`・`ci-gates.yaml` は今は当たらない）は、`elsewhere` にするか manual にする。**共通の入口 `scripts/ci/ci_scope.d/_base.json` の gates は変えない**（共通の入口なので PM が見る）
- manual は README（断片の置き方の説明）と ai-team.yaml・ci-gates.yaml だけで、理由は 15 字以上。それ以外の層を manual にしない
- layer_audit 自身を check に書かない（無限に回る）
