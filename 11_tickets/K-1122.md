## 目的

チケットの範囲の回の web の組（G48・`scripts/ci/web_run.py g48`）は、`op_gate.py --rows-in <流した試験>` で、流した試験のファイルに書かれた行 ID の行だけを照らす（K-177）。今の読み方は、ファイルの字の全部から `\b<ID>\b` を探すので、**コメント**に書いた別の画面の行 ID まで照らす。

実例（K-1151・回 45194457230・先頭 e63348fac）：`apps/web/tests/k/k363-remove-pc.spec.ts` の 217 行目のコメント「…K57-UI-016 が見ている」に当たり、K57-UI-016（結果 PASS・試験は connect-pc の spec）を照らした。その回では connect-pc の spec は流れていないので「PASS だが行 ID を名前に持つ実ブラウザのテストが無い」で赤。K-1151 の外の字が原因で葉が止まる。見立ては `.ticket-flow/out/K-1151/ci-red-PMへ.md`。

PM の決め（作り方・2026-11-24 06:30 案 A）：
1. 照らす行は「流した試験のファイルの**試験の題**に出る行 ID」だけ。題は次の 2 つの和
   - **字で書いた題**：`test`・`it`・`describe`（前に `.` が無い呼び名）と、その後の `.describe`・`.only`・`.skip`・`.fixme`・`.fail`・`.serial`・`.parallel`・`.concurrent`・`.todo` の続きを呼ぶ式の、最初の引数が字（'…'・"…"・`…`）のときのその字。テンプレートの `${…}` の中は題の字に数えない。型の部品 `row(R["<ID>"], …)`（`apps/web/tests/_lib/row.ts`・題は `${r.id} …`）は、`row(` 名前 `[` 字 `]` の字
   - **報告の題**：今の回の報告（`--report`、無ければ op-gate.json の reports。G48 は Playwright の k.json だけ）のうち、ファイルの名前（Playwright の suites[].file・specs[].file。testDir からの道）が流した試験のファイルの道の末尾に当たる試験の題（上の段の題をつないで読む・load_report と同じ）。vitest の報告は G48 で使わないので見ない。`${id}` を配列から作る題（shell-ops.spec.ts・showcase.spec.ts の `row(R[id])` など）はここで拾う
2. コメント（`//`・`/* */`）・題でない字（体の中の字・`re.test("…")` の `.test`・`test.step("…")`・正規表現の字）は数えない。字・正規表現の中の `//`・`/*` はコメントの始まりにしない
3. 字で書いた題は報告に無くても照らす（題に在るのに流れていない行は今までどおり赤）
4. 読めない字（閉じないコメント・字・テンプレート）でも落ちない（Traceback を出さない）。閉じない所から後は数えない
5. 全部の回（`--all`）・`--task`・`--wave` の照らし方は変えない。行 ID の形 ID_RE も変えない

## リスクと懸念

- 字で書いた題でなく、報告にも出ない題（`${id}` で作る題で、その試験が 1 本も流れなかった）は照らさない。前は配列の字（`["USH-01-010", …]`）で照らしていた。ファイルが読めず 1 本も流れない回は、試験の道具が先に赤で止まる（web_run は試験が落ちたら op_gate まで行かない）ので、黙って緑にはならない
- `test`・`it`・`describe` を別の名前で import して使う形（`import { test as base }` の `base("…")`）は字で書いた題に数えない。流れれば報告の題で拾う
